## 1. 多身份系统（Multi-Persona / Account Switching）

**来源**: 2026-04-11 用户口述
**状态**: 未开始
**优先级**: **P1**

### 1.1 需求描述
目前 Settings 已经有"身份（Persona）"的概念，但只支持单一身份。参考其他"小手机"类应用，用户应该可以拥有**多个身份**并在它们之间**切换**。

### 1.2 功能点拆解

#### A. Settings 层：多身份管理
- 用户在设置里可以**创建 / 查看 / 切换 / 删除**多个身份
- 每个身份独立保存：头像、昵称、（未来可能还有个性化配置）
- 有一个"当前激活身份"的概念

#### B. 星语（XingYu）App：切换账户模块
- App 首次进入需要选一个身份——从 Settings 里已有的身份中**选一个**作为当前星语账号
- 支持**切换账户**（不叫"登出"，直接切到另一个身份）
- **首次使用某身份**：自动把所选身份的头像、昵称填充到星语个人资料
- **之后**：头像、昵称**可以在星语内独立修改**，不回写到 Settings 身份
- **切换后再切回来**：之前在星语内改过的头像/昵称**保留**（按身份维度持久化）

### 1.3 关键决策（已确认 ✅）
1. **App 内改动不回写系统身份** — 系统身份是"账号来源"，App 内资料是"应用内资料"，解耦。首次选择身份时只是"初始值带入"。
2. **每个 App 独立切换账户** — 未来如果有微信、Snapchat 等，各自独立。同一台"手机"上不同 App 可以用不同身份。
3. **无需数据迁移** — 直接改结构，老数据清空重来即可。
4. **按身份维度持久化 App 内资料** — 星语里每个身份都有自己独立的一份 profile，切换账户时从对应身份的资料读取（不是清空）。
5. **术语**：叫"切换账户"，不叫"登录/登出"。

### 1.4 优先级理由
- **P1（本阶段做）** — 这是一个结构性改动，会影响 Settings store、星语 store、未来所有需要"身份"的 App。越早做越好，但不是阻塞当下的 bug，所以不是 P0。
- 建议和"星语个人资料头像封面自定义"（`docs/plan/2026-04-11-1100-星语个人资料头像封面自定义.md`）**合并规划**——两者都在动星语的 profile 数据。

### 1.5 涉及文件（预估）
- `src/platform/stores/` — 新增或改造 persona store，支持多身份数组
- `src/apps/Settings/pages/PersonaPage.tsx` — 改为列表 + 增删改 + 切换
- `src/apps/XingYu/xingYuDataStore.ts` — 增加"当前账户"字段 + 按身份分区的 profile map
- `src/apps/XingYu/pages/Settings.tsx` — 增加"切换账户"入口
- 星语新增 `AccountPicker` 页面（首次进入 + 切换账户时展示）

## 3. Settings：角色管理页两处微调

**来源**: 2026-04-11 用户口述
**状态**: 未开始
**优先级**: **P2**
**关联**: 本质上是任务 #1 "多身份系统" 的前置清理。做 #1 时可以顺手一并处理。

### 3.1 文案：「虚拟恋人」→「角色」
- 当前入口写的是"虚拟恋人"，但这个概念实际就是 `personaStore` 里的 **Persona（角色）**，不是"恋人"
- 全局统一改成「角色」
- 涉及：Settings 入口文案、页面标题、所有相关文案

### 3.2 移除角色列表的"勾选"标记
- **现象**：进入 Settings → 角色管理后，点任一角色会直接进入编辑页；退回来发现该角色被打了"✓"
- **问题**：用户无法理解这个勾的含义 —— 不像 iOS 设置里"当前选中项"那样有明确语义
- **动作**：**直接去掉这个勾**

#### 为什么去掉是对的（关键决策依据）
这和任务 #1 决策 #2 "**每个 App 独立切换账户**" 是一致的：
- 如果每个 App 独立选身份（星语选 A、未来微信选 B），那"系统级当前激活角色"这个概念**本身就没意义**
- Settings 的角色管理页应该只是**"我拥有哪些角色"的清单**，不应该有"当前选中的那一个"
- `personaStore.activePersonaId` 本质上会变成**遗留字段**（Settings 不再写它；各 App 自己维护自己的 activePersonaId）

#### 后续影响（做 #1 时要一并处理）
- `personaStore` 的 `activePersonaId` 字段要么删掉，要么只留给未加载独立身份系统的老 App 作为默认值
- Settings 里任何依赖 `activePersonaId` 的地方要切到"无系统默认"的模型

### 3.3 涉及文件（预估）
- `src/apps/Settings/pages/PersonaPage.tsx`（列表 UI + 勾选逻辑）
- `src/apps/Settings/SettingsHome.tsx`（入口文案"虚拟恋人"→"角色"）
- Grep 全项目搜 "虚拟恋人" 确保没漏
