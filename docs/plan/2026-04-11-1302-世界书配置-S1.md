# 世界书配置 一期 (S1)

日期：2026-04-11
里程碑定位：角色系统扩展 M? → 世界书 S1（最小可用版本）
相关调研：`docs/research/sillytavern-worldinfo-config-layer.md`

## 用户需求

1. 在「设置」里增加一个「世界书」配置页，能**创建、编辑、删除**世界书。
2. **命名叫"世界书"不叫"世界卡"**。
3. **不做关键词匹配** —— 一期不实现根据聊天内容动态命中条目。所有启用的条目全部注入系统 prompt。
4. 最小字段：
   - 世界书：`id / name / description / enabled / entries / createdAt / updatedAt`
   - 条目：`id / title / content / enabled / order`
5. **全局作用域** —— 一期不做"绑定到特定角色"，所有启用的世界书对所有 AI 聊天都生效。
6. 预设一本空世界书作为首次体验的引导。
7. UI 必须符合 iOS 设置风格（复用现有 `List` / `ListSection` / `ListRow` / `TextArea` 组件）。

## 关键决策

### D1：所有启用条目全量注入（无关键词匹配）
一期走最朴素的策略：任何 `enabled=true` 世界书下的任何 `enabled=true` 条目，按 `order` 升序拼接后作为 **system prompt** 的一段额外内容，注入到现有 `systemChunks` 数组的第一项前面。

拼接格式：

```
[世界书]
## 条目标题 1
条目内容 1

## 条目标题 2
条目内容 2
```

原因：规避关键词匹配的复杂度，同时用户自己控制条目数量 = 控制 token 消耗。关键词匹配放到二期。

### D2：全局作用域，不与角色绑定
一期**不在 `characterStore` 或 `xingYuDataStore` 中加 `worldBookIds` 字段**。世界书对整个应用生效。二期再做"给角色绑定专属世界书"。

### D3：存储方案 — zustand + persist（localStorage）
走现有 `src/platform/stores/` 模式，与 `characterStore.ts` 保持一致：
- `partialize` 只持久化 `books` 数组，不持久化 `editingBookId` / `editingEntryId` 这类临时编辑状态
- 自动迁移：不需要（从零开始）

### D4：条目用 array，不用 SillyTavern 的 `{[uid]: entry}` map
简化 schema，`order` 字段决定显示与注入顺序。新建条目默认 `order = 当前最大 order + 10`。

### D5：导航三级栈
使用现有 `settingsNavStore` 的 push/pop 机制：
```
home → worldBooks → worldBookEdit → worldBookEntryEdit
```

通过 `editingBookId` / `editingEntryId` 做编辑对象的 handoff（参考 `CharactersPage` → `CharacterEditPage` 的 `setActive` 模式）。

### D6：预设一本空世界书
Store 初始化时塞一本名为"我的世界书"的空书（无条目），让用户第一次进来直接能点进去加条目，不必先建书。

### D7：标题字段双重用途
`title` 字段同时作为 UI 列表显示名 + Prompt 中的 `## 标题`。**不拆分 memo/display 两个字段**（ST 踩过的坑——hiPhone 用最简方案）。

### D8：保存策略 — 实时写入（类似 Notes）
用户改动立即写入 store（每次 `onChange` 触发），不需要"保存按钮"。返回即保存。

## 数据模型

```ts
// src/platform/stores/worldBookStore.ts

export interface WorldBookEntry {
  id: string;
  title: string;
  content: string;
  enabled: boolean;
  order: number;
}

export interface WorldBook {
  id: string;
  name: string;
  description: string;
  enabled: boolean;
  entries: WorldBookEntry[];
  createdAt: number;
  updatedAt: number;
}

export interface WorldBookState {
  books: WorldBook[];
  editingBookId: string | null;      // 编辑 handoff，不持久化
  editingEntryId: string | null;     // 编辑 handoff，不持久化

  // 世界书 CRUD
  addBook: (name?: string) => string;
  updateBook: (id: string, patch: Partial<Omit<WorldBook, 'id' | 'entries'>>) => void;
  removeBook: (id: string) => void;
  toggleBook: (id: string) => void;

  // 条目 CRUD
  addEntry: (bookId: string, title?: string) => string;
  updateEntry: (bookId: string, entryId: string, patch: Partial<Omit<WorldBookEntry, 'id'>>) => void;
  removeEntry: (bookId: string, entryId: string) => void;
  toggleEntry: (bookId: string, entryId: string) => void;

  // 编辑 handoff
  setEditingBook: (id: string | null) => void;
  setEditingEntry: (id: string | null) => void;

  // Prompt 注入
  buildSystemPromptChunk: () => string;
}
```

### `buildSystemPromptChunk()` 规范

- 遍历 `books` 中所有 `enabled === true` 的书
- 对每本书，取所有 `enabled === true` 的条目
- 按 `order` 升序拼接
- 每条格式：`## ${title}\n${content}`
- 条目间用 `\n\n` 分隔
- 所有条目前加一行 `[世界书]` 标记
- 若无任何启用条目，返回空字符串（调用方据此跳过注入）

## 测试计划

### 单元测试（`worldBookStore.test.ts`）

1. **初始状态**：默认有 1 本空书
2. **addBook**：追加到末尾，返回 id
3. **updateBook**：patch 字段不影响 entries；`updatedAt` 被更新
4. **removeBook**：从列表删除；删除当前 editingBookId 时清空 editing
5. **toggleBook**：enabled 取反
6. **addEntry**：追加到末尾，order 自动递增
7. **updateEntry**：patch 字段
8. **removeEntry**：从 entries 删除
9. **toggleEntry**：enabled 取反
10. **buildSystemPromptChunk 空场景**：全部 disabled 时返回空串
11. **buildSystemPromptChunk 单条**：返回 `[世界书]\n## title\ncontent`
12. **buildSystemPromptChunk 多条排序**：按 order 升序
13. **buildSystemPromptChunk 过滤**：跳过 disabled 的书/条目
