# 2026-04-12 M2：活人感增强 — 设备上下文 + 回复后处理

## 用户需求

> 让角色从"能聊天"变成"活着"。

M1/M1.5 完成了 prompt pipeline 和记忆压缩，角色已经知道时间、用户名、有长期记忆。M2 利用手机的设备上下文 + 回复后处理，进一步提升"活人感"。

## 现状

- assemblePrompt Phase 3 已有时间锚定 `[当前时间：...]`
- appRuntimeStore 有 `activeAppId`，但 prompt 里零引用
- weatherStore 有实时天气数据，但 prompt 里零引用
- LLM 回复直接写入 store，无任何后处理（可能出现"我是 AI"、markdown 代码块等）

## 关键决策

### D1. 设备上下文注入位置

作为 Phase 3（post-history）的一部分，紧挨时间锚定。理由：
- post-history 是 LLM 最后读到的内容，影响力最大
- 设备上下文是"此刻"的状态，放在最末尾最合理

### D2. 设备上下文数据源

从 weatherStore 读取天气数据 + 时段。不注入 activeAppId — AI 恋人/朋友不需要知道用户在用哪个 App，这更像监控而非自然互动。

不在 `assemblePrompt` 纯函数里直接读 store（保持纯函数特性）。改为在 `PromptInput` 新增 `deviceContext?: string` 字段，由调用方（xingYuDataStore）组装后传入。

### D3. buildDeviceContext 放在哪

新建 `src/platform/ai/deviceContext.ts`，导出 `buildDeviceContext(): string`。
这个函数读 store、组装字符串。由 xingYuDataStore 调用后传给 assemblePrompt。

### D4. 天气描述映射

复用 Weather app 已有的 `getCondition(code)` 函数。该函数返回 `{ label, icon }`，我们只需要 `label`。

### D5. Regex 后处理

新建 `src/platform/ai/replyFilters.ts`，导出 `filterReply(text: string): string`。
在 streamChat 结束后、写入 store 前调用。全局硬编码规则：
- 防止角色自称 AI
- 移除 markdown 代码块、标题、粗体整句
- 不做角色级配置（M2 scope 内不需要）

### D6. 时段描述

根据小时数：深夜(0-5)、早上(6-8)、上午(9-11)、中午(12-13)、下午(14-17)、傍晚(18-19)、晚上(20-23)
