# M4.2 S3 — defaultXingYuRenderer + parseReply Extensions

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the stub `DEFAULT_XINGYU_RENDERER` shipped in S1 with the **lossless** default renderer, and extend `parseReply` to recognize the unified `{type:'action', name, params}` shape while preserving backwards compatibility with the legacy `{type:'sticker'}` / `{type:'signature'}` items.

**Architecture:** `defaultXingYuRenderer.ts` exports the canonical renderer as a standalone module, then `replyRendererRegistry.ts` re-imports it to replace the stub. The renderer owns the no-loss rules in spec §2 / D2:

- `text` → `<speaker>: <content>`
- `action` → `<speaker>: 【<name>】<k=v ...>`
- `sticker` (legacy) → `<speaker>: [表情 <stickerId>: <content>]`
- `signature` (legacy) → `<speaker>: [更新签名: <text>]`

`parseReply` gains an `action` branch; validates `name:string` and `params:Record<string, unknown>`; preserves prior three-level-fallback behavior (direct parse → code block → bracket extraction).

**Tech Stack:** TypeScript, Vitest.

**Parent spec:** [`docs/superpowers/specs/2026-04-19-m4.2-tool-registry-and-rendering-design.md`](../superpowers/specs/2026-04-19-m4.2-tool-registry-and-rendering-design.md) §2 + §10 + D2 + D6

```typescript
// src/platform/ai/defaultXingYuRenderer.ts
/**
 * Lossless default reply renderer — used whenever an app hasn't
 * registered its own in replyRendererRegistry. Produces natural-language
 * text that a human + the LLM can both read, while preserving every
 * decision-relevant identifier (stickerId, action params).
 *
 * Rendering rules (spec §2 + D2):
 *
 *   text       → "<speaker>: <content>"
 *   action     → "<speaker>: 【<name>】<k=v> <k=v> …"
 *   sticker*   → "<speaker>: [表情 <stickerId>: <content>]"
 *   signature* → "<speaker>: [更新签名: <text>]"
 *
 *   * legacy item types, kept during XingYu's transition to tool-based actions
 *
 * See docs/superpowers/specs/2026-04-19-m4.2-tool-registry-and-rendering-design.md §2
 */

import { parseReply, type ReplyItem } from './replyParser';
import type { ReplyRenderer, ReplyRenderContext } from './replyRendererRegistry';

function formatParams(params: Record<string, unknown>): string {
  return Object.entries(params)
    .map(([k, v]) => `${k}=${typeof v === 'string' ? v : JSON.stringify(v)}`)
    .join(' ');
}

function renderOne(item: ReplyItem, ctx: ReplyRenderContext): string {
  if (item.type === 'text') {
    return `${ctx.speakerName}: ${item.content}`;
  }
  if (item.type === 'action') {
    const paramStr = formatParams(item.params);
    const tail = paramStr ? `${paramStr}` : '';
    return tail
      ? `${ctx.speakerName}: 【${item.name}】${tail}`
      : `${ctx.speakerName}: 【${item.name}】`;
  }
  if (item.type === 'sticker') {
    return `${ctx.speakerName}: [表情 ${item.stickerId}: ${item.content}]`;
  }
  // signature
  return `${ctx.speakerName}: [更新签名: ${item.text}]`;
}

export const defaultXingYuRenderer: ReplyRenderer = {
  render(raw, ctx) {
    const items = parseReply(raw);
    return items.map((i) => renderOne(i, ctx)).join('\n');
  },
};
```
