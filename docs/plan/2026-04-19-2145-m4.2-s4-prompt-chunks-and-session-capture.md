# M4.2 S4 — promptAssembly Chunks 6.5 / 7 / 8 + Session Registry Capture

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Thread app-level state into the System block. `promptAssembly` grows three new chunks (`6.5 [当前任务]`, `7 [回复格式]` unified template, `8 [可用动作]` tool list), driven by `PromptInput` additions. `chatWithCharacter` captures the three registry snapshots at session creation and passes them through. The legacy `availableStickers` + `formatOverride` paths stay in place for heartbeat (untouched this milestone).

**Architecture:**

```
PromptInput gets three new fields (all optional during transition):
  currentAppId?: string
  availableTools?: ToolDefinition[]
  appSystemPromptSnapshot?: string

Session capture (inside chatWithCharacter in ai.ts):
  const currentAppId = capturedAppId ?? null;
  const availableTools = currentAppId ? getTools(currentAppId) : [];
  const appSystemPromptSnapshot =
    currentAppId ? (getAppSystemPrompt(currentAppId)?.() ?? undefined) : undefined;
  // freeze these into session state; every callLLM reuses them

buildSystemBlock picks up the three new chunks AFTER the existing chunks
1-6 and BEFORE chunks 7/8, so:
  1 character.systemPrompt
  2 aiConfig.systemPrompt
  3 worldBook
  4 baseline (name/description/personality/scenario)
  5 persona
  6 messageExamples
  6.5 [当前任务] <appSystemPromptSnapshot>    ← new, app-derived
  7 [回复格式]                                  ← rewritten: unified template
  8 [可用动作]                                  ← new, tool-registry-derived
  (legacy [可用表情包] + formatOverride still selectable for heartbeat)
```

The legacy `availableStickers` / `formatOverride` paths still exist so heartbeat / any caller that hasn't migrated keeps working. When `formatOverride` is provided, chunks 6.5/7/8 are suppressed.

function systemBlock(input: PromptInput): string {
  const { messages } = assemblePrompt(input);
  const sys = messages.find((m) => m.role === 'system');

```typescript
  // 7-8 (+ 6.5) — Format / tools / app-task chunks.
  //
  // Priority (first match wins):
  //   1. formatOverride  → legacy ReAct path (heartbeat). Everything else skipped.
  //   2. Unified M4.2    → 6.5 [当前任务] + 7 [回复格式] + 8 [可用动作].
  //                        Triggered when EITHER appSystemPromptSnapshot OR
  //                        availableTools is provided (app has migrated).
  //   3. Legacy XingYu   → old 7 [回复格式] + [可用表情包]. Fires when availableStickers
  //                        is set AND the M4.2 path didn't trigger. Used only by
  //                        pre-migration callers (heartbeat passes availableStickers=undefined;
  //                        formatOverride wins; see §8).
  if (formatOverride) {
    chunks.push(formatOverride);
  } else if (appSystemPromptSnapshot !== undefined || (availableTools && availableTools.length > 0)) {
    // 6.5 — app-specific "current task" snapshot (optional)
    if (appSystemPromptSnapshot && appSystemPromptSnapshot.trim()) {
      chunks.push(`[当前任务]\n${appSystemPromptSnapshot.trim()}`);
    }
    // 7 — unified reply format
    chunks.push(
      [
        `[回复格式]`,
        `你用 JSON 数组回复，每条消息是以下两类之一：`,
        ``,
        `1. 叙述 / 对白：`,
        `   {"type":"text","content":"..."}`,
        ``,
        `2. 执行动作：`,
        `   {"type":"action","name":"<动作名>","params":{...}}`,
        ``,
        `示例：[{"type":"text","content":"欢迎"},{"type":"action","name":"<动作>","params":{...}}]`,
        ``,
        `只输出 JSON 数组，不要其他内容。`,
      ].join('\n'),
    );
    // 8 — Tool Registry derived list (optional)
    if (availableTools && availableTools.length > 0) {
      const toolLines = availableTools.map((t) => {
        const params = Object.entries(t.parameters)
          .map(([k, v]) => `${k}: ${v}`)
          .join(', ');
        return `- ${t.name}: ${t.description}\n  参数: { ${params} }`;
      });
      chunks.push(`[可用动作]\n${toolLines.join('\n')}`);
    }
  } else {
    // Legacy path — pre-migration XingYu style
    const hasStickers = availableStickers && availableStickers.length > 0;
    const formatLines = [
      `[回复格式]`,
      `你必须用 JSON 数组格式回复，每条消息是数组中的一个对象。像真人发微信一样，发多条简短消息而不是一条长消息。`,
      `文字消息格式：{"type":"text","content":"消息内容"}`,
    ];
    if (hasStickers) {
      const example = availableStickers![0]!;
      formatLines.push(
        `表情包消息格式：{"type":"sticker","stickerId":"表情ID"}`,
      );
      formatLines.push(
        `示例：[{"type":"text","content":"哈哈好的"},{"type":"sticker","stickerId":"${example.id}"}]`,
      );
    } else {
      formatLines.push(
        `示例：[{"type":"text","content":"你好呀"},{"type":"text","content":"今天过得怎么样？"}]`,
      );
    }
    formatLines.push(
      `修改个性签名：{"type":"signature","text":"新的签名内容"}`,
      `个性签名会显示在你的星球主页上，用来表达你当下的心情或状态。注意：签名不要改太频繁，只在心情或状态明显变化时才更新。`,
    );
    formatLines.push(
      `规则：`,
      `- 用用户的语言回复，保持角色性格`,
      `- 每条消息简短自然，像真人聊天。不要一次发很长的文本，拆成多条短消息更有活人感`,
      `- 不要使用动作描述（如 *叹气*、*微笑*）`,
      `- 不要使用 markdown 格式`,
      `- 只输出 JSON 数组，不要输出其他内容`,
    );
    if (hasStickers) {
      formatLines.push(
        `- 表情包穿插在文字消息之间使用能提升活人感，适度使用，不要每条都发`,
        `- stickerId 必须使用下方列表中存在的 ID，不要编造`,
      );
    }
    chunks.push(formatLines.join('\n'));
    if (hasStickers) {
      const stickerList = availableStickers!.map((s) => `- ${s.id}：${s.description}`).join('\n');
      chunks.push(`[可用表情包]\n你可以发送以下表情：\n${stickerList}`);
    }
  }
```
