## What landed

### New platform layer — character memory

- `src/platform/ai/characterMemoryStore.ts` — per-character conversation
  stream. Zustand-backed, IDB-persisted (new `characterMemory` object
  store, DB version bumped to v4). Entries carry `speakerId` and keep
  `content` byte-identical to what was exchanged with the LLM (raw JSON
  for XingYu assistant replies; text for user input + derived
  placeholders for images/stickers/forwards).
- `src/platform/ai/buildMemoryEntry.ts` — pure conversion from
  xingYuDataStore `Message` to a `MemoryEntry` shape. Quote references
  are expanded inline; forward cards flatten into labelled blocks;
  `[AI 回复失败]` / `[未配置 AI 服务]` placeholders are filtered out.
- `src/platform/ai/memoryWriter.ts` — `_appendMessage(msg, source)`
  unified write helper that updates xingYuDataStore.messages AND mirrors
  into memoryStore (with cross-write to AI-AI participants).
- `src/platform/ai/characterMemoryCompression.ts` — auto-triggered
  compression (runs on post-append hook, de-duped per character, only
  compresses when token budget crossed). Replaces conv-level
  `triggerCompression` entirely.

### `@hiphone/ai` SDK — both levels

- **Level 1 (pure AI):** `complete` / `streamComplete` / `getCharacters`
  / `extractPlainText`, plus typed exceptions `AIUnavailableError` /
  `AICharacterNotFoundError` / `AIAbortedError`.
- **Level 2 (character chat):** `chatWithCharacter(charId, { persistent
  })` returns a `ChatSession` with `send` / `streamSend` / `append` /
  `replyToLast` / `streamReplyToLast` / `abort` / `history`. Opts
  `{ mirror?: boolean }` on every method. The six-row rules table from
  the spec §4 is exercised in `ai.session.test.ts`.
- Registered in the sandbox moduleMap as `@hiphone/ai`.

### promptAssembly refactor

- Format flip: out goes the first-person labelled system block
  (`[对话记录]\n[HH:MM] 我：...`). In comes **role alternation + speaker
  name prefix** (`user: 小米：你好` / `assistant: <raw JSON>`).
- Data source: `memoryEntries` + `currentCharId` + `charactersById`
  required. `history` / `summary` / `summaryUpToTimestamp` /
  `characterSenderId` / `senderNames` fields deleted.
- Internals deleted: `buildLabeledHistory` + `messageToContent` + legacy
  `buildHistory` branch (~230 LoC). Render reduces to ~30 lines.

### XingYu / heartbeat / aiChatEngine migration

- All `setState({ messages: [...] })` append sites route through
  `_appendMessage` — including heartbeat's `send_message` tool and
  aiChatEngine's bubble append.
- `scheduleAICharacterReply` writes the raw assistant JSON to
  memoryStore as a single entry before bubble delivery (fixes: before
  this release, only the user side of AI chats reached memory).
- `collectCharacterHistory` deleted (no more callers).
- `heartbeat`'s and xingYu's `triggerCompression` calls removed; both
  rely on the memoryStore auto-trigger.
- `Conversation.summary` + `Conversation.summaryUpToTimestamp` schema
  fields deleted.

### Demo fixtures

- `/tmp/ai-translator.zip` — `complete()` translates Chinese → English.
- `/tmp/ai-chat.zip` — session multi-turn with persistent toggle.

## UX changes users will notice

### AI characters "forget once" on first boot after upgrade

memoryStore is NEW storage. It starts empty the first time you open the
app after this release — every character has no recollection of prior
XingYu conversations. From that first boot onward, every XingYu / user-
app / heartbeat exchange populates memoryStore automatically.

This is intentional. Migration tooling was considered higher risk than
this one-time UX bump.

### Prompt format change

Models now see prior turns as `role: user` / `role: assistant` messages
instead of one big `role: system` narration. User content is prefixed
with the speaker's display name (e.g. `小米：你好`) — so group-chat /
AI-AI observation still disambiguate correctly. assistant content is
passed through byte-identically, preserving `stickerId` / signature
actions / multi-bubble intent the model originally emitted.

Observable downstream effect: models keep stickerId picks consistent
across turns more reliably, because they can see their own prior
outputs verbatim instead of reconstructed placeholder text.
