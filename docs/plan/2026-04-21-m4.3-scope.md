# M4.3 Scope Decision

**Date:** 2026-04-21
**Status:** §1 shipped (2026-04-26) · §2/§3 pending
**Prereq:** M4.2.5 shipped (HEAD `0ed5cee`)

记录 M4.3 做 / 不做 / 延期做的决策。正式的 M4.3 spec 等具体开工时再写。

## IN scope — M4.3 要做

### 1. Heartbeat 迁入 Tool Registry + agent-mode tool-result 回灌

**现状问题：**
- `heartbeatAgent.ts` 用自己的 ReAct prompt（`formatOverride`）绕过统一格式
- 工具名、描述硬编码在 `heartbeatPrompt.ts`，和 XingYu / auction 的 Tool Registry 机制不通
- 工具执行失败（参数错、查询无结果）时，错误被静默吞掉或拼成文本塞回 observation，格式混乱

**目标：**
- Heartbeat 的 13 个工具通过 `registerTools('heartbeat', ...)` 走正规 Tool Registry
- ReAct 循环改成标准 `{type, param}` 协议（删 `parseReactOutput`）
- 工具执行出错 → `injectSystemEvent` 以 system role 喂回给 LLM → 下一轮 LLM 能根据错误自适应（类似 S2 的 retry，但这里是**工具报错**而非**格式错误**）

**影响文件：**
- `src/platform/ai/heartbeatAgent.ts` — 主 rewrite
- `src/platform/ai/heartbeatPrompt.ts` — 删除（tools 进 registry，prompt 自动生成）
- `src/platform/ai/heartbeatTools.ts` — 注册为 Tool Registry 项
- `src/platform/ai/promptAssembly.ts` — 可能可以删掉 `formatOverride` 参数（heartbeat 不再需要）

**最大收益**：`heartbeatAgent.ts` 能瘦身一半以上；未来加新 agent 直接走统一基建。

**Status:** ✅ Done (2026-04-26). Implementation: `docs/plan/2026-04-25-0119-m4.3-s1-heartbeat-tool-registry-impl.md`. Spec: `docs/superpowers/specs/2026-04-25-m4.3-s1-heartbeat-tool-registry-design.md`.

### 2. Settings → AI → 工具 页面

**做什么：**
- 新建 `src/apps/Settings/pages/AIToolsPage.tsx`
- 列出所有已安装 app + 其注册的工具
- 每个工具一个 `<ToggleRow>` 控件
- 持久化用户的 disabled-tools 列表
- `toolRegistry.getTools(appId)` 返回时过滤掉被禁用的

**新增 store：**
```ts
// src/platform/ai/disabledToolsStore.ts
interface DisabledToolsState {
  disabled: Record<string, Set<string>>;  // appId -> Set<type>
  setDisabled(appId: string, type: string, disabled: boolean): void;
  getDisabled(appId: string): ReadonlySet<string>;
  clearApp(appId: string): void;  // 卸载 app 时调用
}
```

**边界：**
- 全部工具都被禁用 → 设置页给 warning："关闭全部工具后 AI 可能无法正常回复"
- 新装 app 默认全部启用
- `installer.uninstall` 调 `disabledToolsStore.clearApp` 清理

### 3. 静态 `aiTools` manifest 字段（限定用途：设置页展示）

**关键决策**（经用户确认）：**工具的实际注册仍走代码**（`registerTools(appId, [...])`），保留动态能力。Manifest 只新增一个**静态副本**字段，纯粹给设置页展示用。

**为什么不用动态？**
- 很多 app 的 tool 描述 / 参数涉及运行时状态（XingYu 表情清单、auction 的 items 列表等），函数化注册更灵活
- 完全 declarative 会丢失 `appSystemPrompt` 的动态能力（那本来就是函数）

**为什么需要静态副本？**
- 设置页在 app 未 mount 时也需要列出工具（让用户能提前配开关）
- App Store 详情页展示"此 app 提供哪些工具"时，不想为了显示一个列表先装 + mount 整个 app

**Manifest 扩展：**
```json
{
  "id": "xingyu",
  "name": "XingYu",
  "entry": "App.tsx",
  "aiTools": [
    { "type": "text",             "description": "发一条聊天消息" },
    { "type": "sticker",          "description": "发一个表情包" },
    { "type": "update_signature", "description": "修改个性签名" }
  ]
}
```

- 只要 `type` + `description`（展示够用；`param` 的 prose hint 对用户无意义，不进 manifest）
- Schema 层面**可选**字段（`aiTools?: SimpleToolInfo[]`）
- 设置页读取优先级：`toolRegistry.getTools(appId)`（运行时已注册）→ fallback to `manifest.aiTools`（静态）
- 运行时实际注册和 manifest 不一致不报错——但可以在 dev mode 给 console.warn
- App 作者要自行维护两处同步（接受这个负担换实现简单）

**实施建议：**
- `manifest.ts` 的 Zod schema 加可选 `aiTools` 字段
- 设置页实现时先用运行时 `getTools`；如果 `appRegistry.has(appId)` 但 `getTools(appId).length === 0`，fallback 到 manifest

## OUT of scope — M4.3 不做

### A. Provider-native tool calling（OpenAI function calling / Anthropic `tool_use`）

**原因：**
- 工作量大（每个 provider 一套 adapter）
- 当前 prompt-describe + parse + retry 已经能工作
- 测试面会爆炸（每个 provider 都要 integration 测试）

**记录点：** spec 里说过的好处依然成立，但现在不是最高优先级。等真的遇到"prompt-describe 导致 tool 准确率不够"的具体问题再触发。

### B. Streaming + retry 语义

**原因：**
- 用户反馈："streaming 感觉不适应我们这套，需要重新设计"
- 当前 `streamSend` / `streamReplyToLast` 单次 yield 的模式本来就是 M4.1 遗留，并非真正流式
- 把 retry 硬塞进流式会和真正 streaming（M4.3+ provider native streaming）的语义冲突

**状态：** 推迟到 provider-native streaming 之后，整体**重新设计** streaming 接口。届时 retry 语义自然融入新设计。

**提醒点：M4.3 完成后提醒用户"streaming 语义需要单独立项讨论"。** 本文档末尾的"Next after M4.3"块也会列出。

## Next after M4.3（备忘录，非本期）

完成 M4.3 后主动提醒用户这些事：

1. **Streaming 接口整体重新设计** — 当前 `streamSend` / `streamReplyToLast` 是假流式（单次 yield）。真正的 streaming（provider-native 增量）跟 retry、tool-call 增量、rendered 渐进累积都有冲突，需要单独立项
2. **Provider-native tool calling** — heartbeat 迁入 Tool Registry 后，原生 tool calling 的价值会更明显（能给 heartbeat 加 `tool_choice: 'required'` 强制调工具）。届时可以开 M4.4 或更后的专项
3. **App Store 远端同步** — M4 早期列过，一直没做。单独立项
4. **AI App Builder V1** — M4 早期列过，单独立项
5. **`appSystemPrompt` 与 `dynamicContext` API 整合** — 两个 API 都做"运行时产一段字符串塞进 prompt"。`appSystemPrompt` 在 session 创建时冻结一次产出 `[当前任务]`,`dynamicContext` 每次 prompt-build 重算产出 `[工具状态]`。功能重叠明显但放置位置和缓存语义不同。M4.3 §1 完成后可以重新评估是否合并成一个统一 API。详见 `docs/superpowers/specs/2026-04-25-m4.3-s1-heartbeat-tool-registry-design.md` Follow-ups 章。
