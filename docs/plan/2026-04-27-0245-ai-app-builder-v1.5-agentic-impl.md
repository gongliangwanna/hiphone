# AI App Builder V1.5 — Agentic Loop Implementation Plan

> Approved design: `~/.claude/plans/stateful-knitting-hammock.md` (also embedded below).
> Execution: superpowers:subagent-driven-development, fresh subagent per stage.

## Goal

Replace V1's one-shot `chatComplete → JSON files → install` flow with a Codex-style **agentic loop**: the LLM operates 9 tools (read/write/delete file, list, compile_check, read_fixture, update_plan, mark_step, finish) inside a ReAct loop. The user sees tool calls + a TODO plan inline in chat.

## Critical isolation constraint

**Must not touch any existing AI feature.** Allowed reuse:
- `chatComplete` (provider call layer)
- `compileTsx` (Sucrase wrapper)
- `validateManifest` + `ManifestError`
- `getAdapter` (provider adapter for endpoint fallback)
- `useAIConfigStore` (read-only)
- `useAIAppBuilderConfigStore` (existing, untouched)
- `installer.install` (final step, untouched)

**Forbidden imports:** `heartbeat*`, `aiChatEngine`, `toolRegistry`, `disabledToolsStore`, `parseReply`. The agent's tool list is private to the agent; never registered globally.

Parses `{thought?, tool, args}` JSON. 3-tier strategy (direct → ```json fence → brace slice). Returns `{tool, args, thought?} | null`. Tests: clean JSON, with thought, fence, prose-prefixed, missing tool field, null-args coercion to `{}`, garbage, empty.

### S4 — `agent/builderTools.ts` + 12+ tests
9 tool executors:

```ts
export interface ToolContext {
  draftId: string;
  // Tools mutate via store dispatch; this carries draftId for manifest.id locking.
}
export type ToolResult = { ok: true; data?: unknown } | { ok: false; error: string };
export const TOOLS: Record<string, ToolHandler>;
export async function executeTool(name: string, args: unknown, ctx: ToolContext): Promise<ToolResult>;
```

Tools:
- `read_file({path})` → file content or `{ok:false, error:'not found'}`
- `write_file({path, content})` → `{ok:true}`. Special case: if `path === 'manifest.json'`, parse JSON, force `id = ctx.draftId`, re-stringify before writing (locked id enforcement).
- `delete_file({path})` → `{ok:true}` even if absent (idempotent)
- `list_files({})` → `{paths: string[]}` sorted
- `compile_check({path?})` — runs `compileTsx` on .tsx/.ts files; runs `validateManifest` on manifest.json. Returns `{ok, errors: [{path, message}]}`.
- `read_fixture({name})` — name in `'todo-app' | 'ai-translator-app'` — returns the fixture's files via Vite `?raw` imports (already wired in V1's `builderPrompt.ts`)
- `update_plan({steps: [{id, title}]})` — replaces plan store steps, all status='pending'
- `mark_step({id, status})` — updates one step
- `finish({summary})` — special: returns `{ok:true, data:{finished:true, summary}}` so the runner can detect termination

Tests: 1 per tool happy path + edge cases (write_file rewrites manifest.id, delete_file on missing, compile_check on broken TSX returns error array, unknown tool name).

### S7 — `agent/builderAgent.ts` + integration test
The loop runner.

```ts
export interface RunAgentInput {
  draftId: string;
  userMessage: string;
  signal?: AbortSignal;
  onTurn?: (event: AgentTurnEvent) => void;
}
export type AgentTurnEvent =
  | { kind: 'agent-text'; text: string }
  | { kind: 'tool-call'; tool: string; args: unknown; result: unknown; ok: boolean }
  | { kind: 'plan-update'; steps: PlanStep[] }
  | { kind: 'finish'; summary: string };
export async function runBuilderAgent(input: RunAgentInput): Promise<void>;
```

Loop body (max 25 iterations):
1. Build messages from store: system prompt + state digest (current files list + plan) + history (with tool calls flattened to assistant/system pairs) + most-recent user message OR last tool result
2. Call `chatComplete` with provider config from `resolveBuilderProviderConfig`
3. Parse with `builderToolParser`
4. On parse fail: 1 retry with stricter reminder; if still fails, emit agent-text with the error and exit
5. If `tool === 'finish'`: emit finish event, break
6. If `tool === 'update_plan'`: emit plan-update event (also writes to plan store via tool executor)
7. Else: execute tool; emit tool-call event with result
8. If parsed `thought` present, emit agent-text event before the tool-call event
9. `signal.aborted` → break

State digest format (kept terse): `Files: ["manifest.json","App.tsx",...]\nPlan: [✓ step1, ⏳ step2, ...]`.

Integration test: mock `chatComplete` with a 5-message script (update_plan → write_file × 2 → compile_check → finish), assert events fired in order, `useAIAppBuilderStore.getState().draftFiles` populated, plan store has the 4 steps.

### S9 — Update `AIAppBuilderApp.tsx`
Replace `generateDraft` call with `runBuilderAgent`. Wire the `onTurn` callback to the new store appenders. Drop the V1 generator-style switch on `result.kind`.

```ts
await runBuilderAgent({
  draftId: id,
  userMessage: text,
  signal: controller.signal,
  onTurn: (event) => {
    const s = useAIAppBuilderStore.getState();
    switch (event.kind) {
      case 'agent-text':  s.appendAgentMessage(event.text); break;
      case 'tool-call':   s.appendToolCall(event.tool, event.args, event.result, event.ok); break;
      case 'plan-update': s.appendPlanUpdate(event.steps); break;
      case 'finish':      s.appendFinish(event.summary); s.setStatus('ready'); break;
    }
  },
}).catch((err) => {
  const msg = err instanceof Error ? err.message : String(err);
  useAIAppBuilderStore.getState().appendAgentMessage(`[运行失败] ${msg}`);
  useAIAppBuilderStore.getState().setStatus('idle');
});
```
