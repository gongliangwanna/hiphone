# 音乐 App UI 全量优化计划

## 用户需求

用户提供了音乐 App 的首页、歌曲列表页、播放页截图，并指出当前 UI “太丑了”。在先前分析中已经列出整体视觉、字体层级、间距、首页头图、底部 Tab、迷你播放器、歌曲列表、全屏播放器、播放控制、可访问性等优化点。用户现在要求“全部优化掉”，因此本次任务目标是把这些视觉和交互问题在现有代码中一次性落地。

## 范围

- 优化 `src/apps/Music` 内的视觉层和基础交互层级。
- 保留现有数据获取、播放队列、搜索、歌词、分享、失败歌曲 toast 逻辑。
- 不触碰当前工作区已有的 AIAppBuilder、AI 平台、系统 NavBar 等未提交改动。
- 不引入新的 UI 框架；沿用 React、motion、lucide-react、现有系统安全区和设计 token。

## 关键决策

1. 音乐 App 继续使用深色模式，但从纯黑大白字改为 iOS 音乐类 App 的分层深色材质：页面底色、专辑色柔光、卡片半透明层、毛玻璃底栏分开。
2. 建立音乐模块局部 design tokens，统一 accent、文字层级、分割线、卡片圆角、玻璃材质和阴影，减少各页面自定义样式漂移。
3. 首页以“可扫读内容货架”为主：降低大标题压迫感，重做推荐 hero、横滑专辑卡、最近播放、专属推荐、新歌速递列表。
4. 浏览页承担“新歌/搜索/分类”的列表质量改造：搜索框、热门专辑、分类卡、结果列表统一为 iOS 行高和截断规则。
5. 广播和资料库保持功能不变，但统一卡片、列表、图标、分组容器样式，避免和首页割裂。
6. 迷你播放器改为 Tab 上方的 iOS 浮层：小封面、歌曲信息、进度线、播放/下一首按钮，作为进入全屏播放器的承接。
7. 全屏播放器重构层级：自适应专辑色背景、封面与歌名分离、标准进度条、清晰播放控制、音量条和底部动作区，不再让封面/标题/控制互相挤压。
8. 测试优先：先补音乐 UI 结构测试，覆盖首页入口、底部 Tab、迷你播放器、全屏播放器核心控件，再进行实现。

## 里程碑

### 阶段 1：测试与共享视觉基建

- 新增音乐 App UI 结构测试。
- 新增音乐模块共享 UI token / 小组件，统一页面背景、标题区、section header、歌曲行、专辑卡、底部留白。

### 阶段 2：首页、浏览、广播、资料库重做

- 首页重做 hero、最近播放、专属推荐、新歌速递。
- 浏览页重做搜索框、热门专辑、分类网格、搜索结果列表。
- 广播页和资料库页统一视觉密度、圆角、材质、列表层级。

### 阶段 3：播放层重做

- 重做 TabBar 毛玻璃系统栏。
- 重做 MiniPlayer，加入进度线和更清晰控制。
- 重做 NowPlaying，自适应背景、封面布局、控制区、音量条、动作区。

### 阶段 4：验证

- 运行音乐 App 相关测试。
- 运行 TypeScript / build 或至少目标测试。
- 启动本地 Vite 服务并用浏览器/截图检查主要界面是否无明显遮挡和文字溢出。

## 验收标准

- 首页、浏览、广播、资料库、全屏播放页都符合 iOS 深色音乐 App 视觉语义。
- 底部 Tab 和 MiniPlayer 使用毛玻璃层，和内容层级分离。
- 播放页封面、歌名、进度、控制按钮不重叠。
- 列表行高、封面、分割线、文字截断一致。
- 测试通过，关键入口和核心播放控件仍然存在。
