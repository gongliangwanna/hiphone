# 音乐 App 性能优化计划

## 用户需求

用户反馈音乐 App 当前有明显卡顿，尤其是：

- 进入多任务时；
- App 被缩小成多任务卡片时；
- 播放页向下拖拽关闭时。

本次任务目标是保留上一轮 UI 优化后的整体质感，但降低实时缩放和拖拽场景下的合成/重绘压力。

## 性能判断

当前音乐 App 的主要风险来自视觉效果：

1. `NowPlaying` 背景使用全屏专辑图叠加 `filter: blur(42px)`，拖拽时整层跟随 transform，容易在每帧造成昂贵合成。
2. `AlbumDetail` 背景也使用大图 `filter: blur(44px)`，进入多任务卡片时需要缩放该高成本层。
3. TabBar、MiniPlayer、共享 glass 样式使用 30px 以上 `backdrop-filter`，在 AppHost 缩放和 AppSwitcher 卡片渲染时成本偏高。
4. 歌词行对非当前行使用 CSS `filter: blur(0.5px)`，在歌词滚动和播放页拖拽时会增加文本绘制成本。
5. 播放页下拉关闭使用原生 pointer move 改 transform，逻辑本身较轻，主要瓶颈是被拖动 subtree 内的模糊背景和多层玻璃材质。

## 关键决策

- 播放页不再使用全屏模糊专辑图做背景，改为基于歌曲名的静态渐变背景，保留氛围但避免实时图片模糊。
- 专辑详情页同样移除大图 CSS blur，改用渐变背景。
- 降低音乐模块 glass blur 强度，减少 `backdrop-filter` 采样成本。
- 歌词行去掉 CSS blur，仅使用透明度、缩放和字重区分层级。
- 在音乐 App 根节点增加布局/绘制隔离提示，减少与 Shell 动画互相影响。

## 验收标准

- 音乐 App 首页、播放页、歌词页仍保持当前视觉方向。
- 播放页下拉关闭时不再拖动全屏模糊图层。
- 多任务缩放时音乐 App 不再包含高成本全屏 CSS blur 背景。
- 音乐 UI 测试和 TypeScript 检查通过。
