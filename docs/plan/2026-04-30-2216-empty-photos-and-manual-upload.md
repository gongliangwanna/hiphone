# 相册清空与手动上传计划

## 用户需求

用户要求：清空相册里面的图片，同时支持手动上传图片。

当前相册使用 `photosData.ts` 中的 60 张 `picsum.photos` 静态模拟图片。相册页面、查看器、搜索页、相簿页和照片小组件都直接读取这份静态数据，因此只改 UI 不够，必须把相册改成可变图库数据源。

## 关键决策

1. 默认图库清空：`allPhotos` 不再生成 mock 图片，初始相册为空。
2. 上传图片转为 data URL 写入 Zustand store；store 使用 `idbStorage` 持久化，避免刷新后丢失用户上传的图片。
3. 保持现有 `Photo.id` 为 `number`，上传时用时间戳加序号生成稳定数字 id，降低对现有查看器和测试的影响。
4. 所有消费方改读动态图库：
   - 照片页按月份分组；
   - 相簿页动态计算“最近项目 / 个人收藏”；
   - 为你推荐和搜索在空图库下显示空状态；
   - 照片查看器从 store 查找图片；
   - 照片小组件在空图库下显示“无照片”，有上传图后自动轮播。
5. 上传入口放在“照片”页大标题右侧，使用 iOS 风格的图标按钮和隐藏 file input，支持多选 `image/*`。

## 验收

1. 初始打开照片 App 时不显示任何 mock 图片。
2. 点击上传入口选择图片后，图片进入照片网格，可打开查看器。
3. 上传图片会持久化到相册数据 store。
4. 空图库不会让为你推荐、相簿、搜索、小组件报错。
5. 相关单测和类型检查通过。
