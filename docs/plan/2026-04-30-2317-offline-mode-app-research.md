# 线下模式 App 调研计划

日期: 2026-04-30 23:17

## 用户需求

用户希望为 hiPhone 增加一个“线下模式 app”。这里的线下模式不是指无网络运行，而是指角色和玩家的互动不再模拟聊天软件里的消息往来，而是模拟两个人在线下真实共处、一起活动、面对面互动。

2026-04-30 23:23 用户进一步澄清：这里的“线下模式”更接近小说式/现场式角色互动，不是优先做真实 AR 或完整生活模拟。核心是 AI 角色不在聊天 App 的消息气泡里说话，而是在某个具体场景中“面对玩家”互动；输出不只有文字台词，还应包含动作、眼神、神态、表情等非语言信息。常见表达方式是用括号承载非语言描写，例如“（她抬眼看向你，声音放轻）……”。因此后续设计应重点研究“场景叙事 + 台词 + 舞台指示/非语言描写”的交互结构。

2026-04-30 23:23 用户再次澄清：不要把线下模式定成死协议，不要要求 AI 必须按固定 JSON 字段或固定枚举输出。更重要的是给 AI 明确场景身份：它不再是在聊天软件里和用户聊天，而是在某个具体线下场景中与玩家面对面互动；它可以自由输出合理的动作、神态、表情、姿态、移动、触碰环境、主动提议或任何符合角色与场景的行为。系统只需要告诉 AI 可以自由发挥，并通过安全、角色一致性和场景合理性做边界约束。

本轮先做外部调研，了解同类产品或相关交互范式如何实现“陪伴感”“在场感”和“非聊天式互动”，暂不进入代码实现。

## 调研范围

1. AI companion / virtual companion 产品中，是否存在非聊天式、场景式、共处式体验。
2. 游戏与虚拟角色产品如何通过房间、行动、日程、状态、事件和动作反馈模拟“在线下一起”。
3. AR / spatial / voice companion 产品如何制造“角色在身边”的感受。
4. 可以迁移到 hiPhone 的产品机制、数据模型和 UI 结构。

## 关键决策

1. 本轮重点调研产品机制和交互结构，不以 UI 视觉稿为主。
2. 把“线下模式”定义为一个独立 app 或 app 模式：以空间/场景/活动为主界面，以角色状态、动作和事件流驱动互动，而不是以消息列表为主界面。
3. 第一版不把 AI 输出定成硬协议；自由小说式场景文本是主表达，括号式非语言描写只是推荐形式，不是唯一格式。
4. 输出时区分已验证的公开产品能力、推断出的设计模式、以及仍需二次验证的信息。
5. 调研结论后续应沉淀为设计规格，再拆分里程碑和实现计划。

## 计划步骤

1. 检索同类 AI companion、virtual friend、AI girlfriend/boyfriend、virtual pet、AR companion、life simulation 产品案例。
2. 提炼非聊天式互动的共性模式。
3. 归纳对 hiPhone 线下模式 app 的信息架构、核心循环和技术实现启发。
4. 形成中文调研摘要，并按需要补充文档。
