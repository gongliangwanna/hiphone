# 在场 App 设计稿修订计划

日期: 2026-05-01 00:04

## 用户反馈

用户基于上一版「在场」设计稿提出以下修订：

- 选择角色区域不要写“AI”，用户可见文案就是“选择角色”。
- 角色数据当前没有关系、上次活动时间等字段，所以角色列表只显示头像和名字。
- 自定义场景方向正确：既可以自己输入，也可以选择预设场景。
- 进入场景后需要解决背景图问题：
  - 当前没有按用户自定义场景生成背景图的能力。
  - App 应内置一批预设背景图。
  - 用户选择预设场景时使用该预设场景绑定的图片。
  - 用户输入自定义场景时，从预设背景图库中随机选择一张合适图片兜底。
- 上一版设计稿里的“场景笔记”含义不清，应去掉或改成更明确的内容。
- 互动内容的生成逻辑需要明确，避免和前面“自由现场式输出”的方向冲突。
- 离开场景页整体方向可以，但“记忆价值”这类当前系统没有的概念要去掉。
- 离开场景页仍保持四项摘要信息。
- 完成后的「在场记录」需要保存起来，之后用户可以查看。
- 已完成记录只能查看，不能继续互动。

## 关键决策

1. UI 文案使用「角色」，不使用「AI 角色」。
2. V1 角色选择卡片只显示头像和名字，不展示关系、最近活动、简介等缺失字段。
3. 场景背景由内置 `PresenceBackdrop` 预设图库提供，不依赖实时生图。
4. 预设场景一对一绑定预设背景；自定义场景随机取一张背景图，并允许后续扩展手动换图。
5. 场景页不展示“场景笔记”；主内容是现场片段流和输入区。
6. 离开总结四项改为：`场景`、`发生了什么`、`情绪变化`、`待续事项`。
7. 退出后产生两份结果：
   - 写入角色记忆的一条总结。
   - 保存在「在场」App 内的只读完成记录。
8. 「在场记录」可从 App 首页进入查看，记录页不能发送消息、不能恢复互动。

## 本轮产出

1. 更新「在场」设计规格。
2. 重新生成一张符合修订要求的 App 设计稿。
