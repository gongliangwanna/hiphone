# 角色编辑简化为角色描述

## 用户需求

用户希望设置里的角色编辑不要再暴露大量分散字段。当前存在角色描述、角色性格、情境、开场白、示例对话、高级配置等输入项，但这些对用户来说本质上都在描述同一个角色。新的编辑体验应收敛为一个核心的「角色描述」字段。

明确要求：

1. 去掉「示例对话」。
2. 去掉「性格 / 情境 / 背景」这类拆分字段。
3. 去掉「开场白」。
4. AI 不会主动找人聊天，因此创建会话或清除记忆时不应自动注入角色开场白。

## 关键决策

1. UI 层只保留角色基础信息和「角色描述」作为角色设定入口。
2. 「角色描述」承担完整角色设定：身份、说话方式、行为边界、关系设定等都由用户写入同一个字段。
3. 旧的 CCV2 兼容字段暂时保留在 `characterStore` 中，避免破坏已有导入导出和持久化数据；但产品编辑路径不再展示这些字段。
4. prompt 组装不再从 `personality`、`scenario`、`messageExamples` 注入角色设定，避免旧字段继续影响 AI。角色设定只来自 `description`，再叠加全局/应用级系统提示词。
5. `firstMessage` 不再用于星语会话初始化或清除记忆后的重注入。AI 只有在用户发消息或系统任务触发时才回复。
6. 列表副标题优先展示 `description`，不再回退到 `personality`。

## 测试计划

1. 新增设置角色编辑页测试，确保被移除字段不会渲染，角色描述仍可编辑。
2. 新增星语数据流测试，确保即使旧角色数据里还带 `firstMessage`，创建会话和清除记忆也不会插入首条 AI 消息。
3. 新增 prompt 组装测试，确保旧 `personality` / `scenario` / `messageExamples` 不再进入系统提示词。
4. 运行相关 vitest 文件，必要时补跑类型检查。
