# App 图标刷新与压缩修复计划

## 用户需求

- 在图标编辑页选择图片后，预览必须立即切换到新图片。
- 保存图标后，详情页、App 设置列表页、桌面/Dock 都应该使用同一个新的 app 图标。
- 保存后的图标需要压缩，体积接近当前内置图标，不要把原图或 512 PNG 直接存进 app profile。

## 问题判断

- 图标编辑页打开时会异步加载当前旧图标；用户快速选择新图片时，旧图标的加载回调可能晚到，并把新选择覆盖回旧图。
- 开发环境使用 React StrictMode，首次 effect cleanup 会把 mounted 标记置为 false；如果第二次挂载没有恢复，真实浏览器里 FileReader/Image 读完后也会被误判为已卸载。
- 图标编辑页解析 app 元数据时没有订阅 profile 变化，保存后同一路由不会主动读取刚写入的自定义图标。
- 裁剪输出目前使用 PNG。对照片类上传图来说，PNG 数据 URL 体积明显偏大，不适合作为长期 profile 存储。

## 关键决策

- 所有图标源加载共用一个递增请求编号，旧请求回调晚到时直接丢弃。
- effect 挂载时恢复 mounted 标记，保证 StrictMode 双调用后仍能处理用户选择的图片。
- 图标编辑页订阅 app profile 变化，并在 `displayIcon` 变化时重新加载当前图标源，保证保存后同页面、返回详情页、返回列表页都能看到新图。
- 裁剪输出改为 512x512 JPEG，并指定质量参数；透明区域先铺白底，避免 JPEG 透明像素变黑。
- 补单测覆盖 StrictMode 上传、旧图标加载晚到、保存后列表页可见新图标，以及压缩格式参数。

## 验证

- 运行 Settings 图标编辑相关单测。
- 运行 TypeScript 类型检查。
- 必要时启动本地页面做一次文件上传冒烟验证。
