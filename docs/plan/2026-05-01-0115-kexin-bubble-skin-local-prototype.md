# 可爱信自定义气泡本地原型

## 用户需求

用户希望可爱信的“我的 → 个性装扮”支持用户上传 CSS、代码、图片来重绘聊天气泡。当前先做一个可用的本地 URL 原型，用真实页面验证效果是否符合预期。

本阶段重点不是完成完整上传器，而是验证架构方向：

- “个性装扮”入口可以进入装扮页面。
- 装扮页面能选择本地示例气泡。
- 聊天页真实文本气泡会按所选装扮重绘。
- 示例装扮需要体现 CSS + 图片资源参与渲染，而不是只换纯色。
- 失败或未选择装扮时回退现有 iOS 风格默认气泡。

## 关键决策

1. 先做 CSS/图片模式，不做 JS 沙箱代码模式。
   - 原因：CSS/图片已经能验证“用户上传资源重绘气泡”的主体验。
   - JS 代码模式涉及 iframe sandbox、AST 校验、超时与 CSP，本阶段只保留接口方向。

2. 使用独立 `bubbleSkinStore` 持久化装扮选择。
   - 不把装扮写进单条消息，用户切换装扮后历史消息一起变。
   - 这符合“我的装扮”的心智，也避免污染消息数据结构。

3. 内置示例也走同一套 `BubbleSkin` 数据结构。
   - 本地示例用于验证未来上传 CSS/图片后的渲染路径。
   - 后续上传 zip/css/assets 时可以落到同一个 store。

4. 聊天页新增 `BubbleRenderer` 抽象。
   - 默认样式保留现有 iOS 蓝/白气泡。
   - CSS/图片装扮通过受控样式对象渲染，先不直接注入任意用户 CSS 到主 DOM。

5. 视觉验收优先看真实聊天页。
   - 本阶段需要启动 Vite 本地服务，并在本地 URL 打开可爱信聊天页截图确认。

## 实施范围

- 新增气泡装扮类型、内置示例和 store。
- 新增“个性装扮”页面。
- 接通 ProfileTab 菜单入口。
- 修改 ChatDetail 文本气泡渲染，使用当前选中的 BubbleSkin。
- 增加最小测试覆盖默认和自定义气泡样式。

## 非目标

- 不做 zip 导入。
- 不做任意 JS 执行。
- 不做任意 CSS 解析/清洗。
- 不改变图片、表情、转发卡片的渲染。
- 不改可爱信以外的应用。

## 验收

- 访问本地 URL 后可从“我的 → 个性装扮”看到本地示例装扮。
- 选择“本地信纸”后，回到聊天页可以看到我的文本气泡呈纸张/贴图风格。
- 选择“默认蓝”后恢复现有 iOS 风格。
- 单测通过；若全量测试因工作树其它改动失败，需要记录与本次原型无关的失败。
