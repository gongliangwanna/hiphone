# 在场 App 记录入口和切换动画修复计划

## 用户需求

1. 去掉首页最下方的“在场记录”入口，只保留右上角记录入口。
2. 修复页面切换动效：当前切换页面时会先卡在中间，再整体移上去，体验不符合 iOS 页面切换预期。

## 根因判断

在场 App 的多个页面直接作为 `AnimatePresence` 子节点渲染在同一个 flex 容器内。切换时旧页面退出动画尚未结束，新页面已经进入普通文档流，两个 `flex-1` 页面会短暂同时占位，导致新页面被挤到下方，旧页面卸载后又回到正确位置，于是出现“卡在中间再移上去”。

## 关键决策

1. 首页只保留顶部导航右侧的 `BookOpen` 入口；底部进入场景按钮下方不再显示记录入口。
2. 记录页测试改为点击右上角入口，避免继续依赖被移除的底部入口。
3. 页面内容区改成 `relative` 的 view stack，所有页面视图用 `absolute inset-0` 叠放，避免动画期间互相占位。
4. 保留现有淡入、横向/缩放过渡参数，只修正布局承载方式，不重做整套动画风格。

## 验证

1. `pnpm vitest run src/apps/Presence`
2. `pnpm exec tsc --noEmit --pretty false`
3. `pnpm build`
4. 用浏览器截图检查首页、场景页、记录页切换。
