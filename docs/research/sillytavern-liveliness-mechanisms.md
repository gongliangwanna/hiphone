# SillyTavern "活人感" 实现机制分析

调研日期：2026-04-10

## 核心论点

"活人感"不是单一功能实现的，而是 **多层机制协同** 的涌现效果。SillyTavern 的架构把这些机制分散在不同子系统中，每个子系统解决"活人感"的一个维度：

| 维度 | 人类对应 | SillyTavern 机制 |
| --- | --- | --- |
| 记得你说过什么 | 短期记忆 | 聊天历史 + Token 预算 |
| 记得以前的事 | 长期记忆 | World Info sticky + 摘要扩展 + 向量记忆 |
| 说话有个人风格 | 语言习惯 | mes_example + personality + instruct preset |
| 知道现在几点 | 时间感知 | {{time}} {{date}} {{weekday}} 宏 |
| 会联想相关话题 | 联想思维 | World Info 递归扫描 |
| 不会突然失忆 | 记忆连续性 | sticky 效果 + 常驻条目 |
| 对不同人有不同态度 | 关系差异 | Persona + characterFilter + Persona Lorebook |
| 有情绪波动 | 情绪状态 | Author's Notes + 变量系统 + depth 注入 |
| 会主动提起话题 | 主动性 | 条件触发 + 变量控制流 |
| 多个人一起聊时表现不同 | 社交场景 | 群聊策略 (natural/list/pooled) |

## 1. 记忆系统：让角色"记得"

### 1.1 短期记忆：聊天历史窗口

```
最近的 N 条消息直接进入 prompt
  ↓
Token 预算裁剪最老消息
  ↓
钉选消息可以保留重要信息不被裁剪
```

**活人感贡献**：角色能引用最近几轮的对话内容，像人一样"接话"。

**局限**：上下文窗口有限，过早的对话会被遗忘。

### 1.2 中期记忆：World Info Sticky 效果

```
用户提到 "生日" → 触发条目 "用户生日是3月15日"
  ↓
sticky = 10 → 接下来 10 轮对话中，即使不再提 "生日"，这条信息仍然存在于 prompt 中
  ↓
10 轮后 sticky 过期 → cooldown 期间不再触发（避免信息重复出现的不自然感）
  ↓
cooldown 结束 → 下次再提 "生日" 时可以重新激活
```

**活人感贡献**：人类不会因为话题切换就立刻忘记刚才说的事。sticky 模拟了"短期记忆的自然衰减"。

### 1.3 长期记忆：摘要 + 向量检索

```
扩展: 1_memory (summary)
  ↓
自动对过长的聊天生成摘要
  ↓
摘要注入 prompt，占用较少 Token 但保留关键信息

扩展: 3_vectors (vectorsMemory)
  ↓
把历史消息做向量嵌入
  ↓
当前对话的语义相似消息被检索出来注入 prompt
```

**活人感贡献**：角色能"想起"很久以前说过的话，不需要用户重复。

### 1.4 知识库记忆：World Info Lorebook

```
条目: { keys: ["咖啡", "cafe"], content: "用户最喜欢的咖啡馆是星巴克南京路店，每次去都点冰美式" }
  ↓
用户说 "我想去喝杯咖啡" → 关键词 "咖啡" 命中
  ↓
条目内容注入 prompt → 角色可以说 "去南京路那家星巴克？要冰美式吗？"
```

**活人感贡献**：角色"记住"了关于用户的具体细节，而不是泛泛回应。

## 2. 时间感知：让角色知道"现在"

### 2.1 宏系统的时间变量

```
{{time}}    → "14:32:00"
{{date}}    → "2026-04-10"
{{weekday}} → "Thursday"
{{isotime}} → ISO 格式
```

这些宏在 prompt 组装时展开，角色能感知：
- 现在是早上还是晚上（调整打招呼方式）
- 今天星期几（"周五了，有什么计划？"）
- 距离某个日期多久（"你的生日快到了"）

### 2.2 World Info + 时间 → 场景感知

```
条目: {
  keys: ["早上好", "morning"],
  content: "现在是早晨，{{char}} 刚起床，声音还有些沙哑"
}

条目: {
  keys: ["晚安", "good night"],
  content: "现在是深夜，{{char}} 在被窝里，手机屏幕亮度调到最低"
}
```

**活人感贡献**：角色的状态随时间变化，不是永远在"真空中"对话。

## 3. 语言风格：让角色"有辨识度"

### 3.1 示例对话 (mes_example)

```
<START>
{{user}}: 你今天怎么样？
{{char}}: 还行吧…就那样。*撩了撩刘海* 你呢，又加班到现在？

<START>
{{user}}: 我饿了
{{char}}: 那你吃啊笨蛋。冰箱里有昨天剩的意面，微波炉转两分钟。别跟我说你连微波炉都不会用。
```

**活人感贡献**：LLM 从示例中学习语气、篇幅、标点习惯、动作描写风格。这是控制角色"说话方式"最有效的手段。

### 3.2 性格描述 (personality) + 后置指令 (post_history_instructions)

```
personality: "傲娇、嘴硬心软、不善表达关心但会用行动表示"

post_history_instructions: "回复时注意：
1. 不要直接说'我担心你'，要通过行为暗示
2. 偶尔用省略号表示犹豫
3. 当用户示好时，先嘴硬再用*动作*表达真实感受"
```

**post_history_instructions 的位置**：在聊天历史之后、生成之前。这是对 LLM 的"最后叮嘱"，影响力极大。

### 3.3 Instruct Mode 的停止序列

```
stop_sequence 控制角色"什么时候闭嘴"
  ↓
如果不设停止序列，角色可能自说自话写出用户的回复
  ↓
合理的停止序列让对话节奏像真人聊天：一次说一段，等对方回应
```

## 4. 联想能力：让角色"会想"

### 4.1 递归扫描

```
用户说 "我们去东京吧"
  ↓
条目 A: { keys: ["东京"], content: "东京是日本首都，上次和用户讨论过想去秋叶原和新宿" }
  ↓ 激活后，content 进入递归缓冲
条目 B: { keys: ["秋叶原"], content: "用户是动漫迷，特别想去秋叶原的 animate" }
  ↓ 被 A 的 content 触发
条目 C: { keys: ["新宿"], content: "用户说过想去歌舞伎町一番街看看" }
  ↓ 同样被 A 的 content 触发
```

**活人感贡献**：一个话题自然带出相关记忆，就像人类的联想思维。用户只说了"东京"，角色就能提到之前聊过的秋叶原和新宿。

### 4.2 次键过滤 (Selective Logic)

```
条目: {
  keys: ["吃饭"],
  keysecondary: ["一起"],
  selectiveLogic: AND_ANY,
  content: "用户想约 {{char}} 吃饭，{{char}} 应该表现出期待但故作矜持"
}
```

只有"吃饭"+"一起"同时出现时才触发。避免用户说"我吃饭了"时角色尬聊"我也想跟你一起吃！"。

**活人感贡献**：理解上下文语义，不做机械的关键词反应。

## 5. 情绪与状态：让角色"有变化"

### 5.1 Author's Notes 作为"内心独白"

```
角色笔记: "{{char}} 现在对 {{user}} 有点生气，因为上次 {{user}} 忘了约定"

depth = 4 → 在最近 4 条消息的位置注入
interval = 1 → 每轮都注入
```

**活人感贡献**：角色的情绪状态持续影响回复，不会一轮生气下一轮就好了。Author's Note 像一个"持续的情绪底色"。

### 5.2 变量系统追踪状态

```
/setvar affection 75        → 好感度 75
/setvar mood angry           → 当前心情: 生气

World Info 条目:
{ keys: ["{{getvar::mood}}"], content: "{{char}} 现在心情是 {{getvar::mood}}" }
```

**活人感贡献**：角色有可量化的内部状态，不同状态触发不同的行为模式。好感度低时冷淡，高时亲密。

### 5.3 World Info 的 delay 效果

```
条目: {
  keys: ["喜欢你"],
  content: "{{char}} 内心动摇了，开始正视自己的感情",
  delay: 3
}
```

用户第一次说"喜欢你"不会立刻触发，要等 3 轮之后才生效。

**活人感贡献**：模拟人类"渐渐接受"的过程，而不是关键词一命中就立刻改变态度。

## 6. 关系感知：让角色知道"你是谁"

### 6.1 Persona 系统

```json
{
  "name": "小明",
  "description": "25岁，软件工程师，{{char}} 的男朋友。性格温和但有时候会忘记重要的事。喜欢打游戏和看动漫。",
  "character_lock": "luna.png"
}
```

**活人感贡献**：角色知道用户的身份、年龄、职业、和自己的关系。不会问出"你叫什么名字"这种破坏沉浸感的问题。

### 6.2 Persona Lorebook

```
与 Persona 绑定的 Lorebook:
条目: { keys: ["工作", "上班"], content: "小明在一家互联网公司做后端开发，经常加班到很晚" }
条目: { keys: ["妈妈", "家里"], content: "小明和妈妈关系很好，每周日会打电话" }
```

只有使用这个 Persona 时才激活，换 Persona 后自动切换知识库。

### 6.3 角色过滤 (characterFilter)

```
条目: {
  keys: ["做饭"],
  characterFilter: { names: ["luna.png"], isExclude: false },
  content: "Luna 会做饭，最拿手的是日式咖喱"
}
```

同一个 Lorebook，不同角色触发不同内容。

**活人感贡献**：信息不会串台，每个角色有自己的"记忆边界"。

## 7. 社交动态：群聊的"活人感"

### 7.1 发言策略

| 策略 | 模拟的人类行为 |
| --- | --- |
| natural | 分析消息提及和角色健谈度，话题相关的角色更容易发言 |
| list | 按顺序轮流，像会议发言 |
| pooled | 最近没说话的人更容易被选中，避免一个人独占 |
| manual | 随机，模拟自然群聊 |

### 7.2 群聊专属开场

同一个角色，单聊和群聊的 first_mes 可以不同：
- 单聊："嘿，就我们两个呢"
- 群聊："大家好~"

### 7.3 Group Nudge

```
"[Write the next reply only as {{char}}.]"
```

在群聊场景中注入，防止角色越权替其他角色说话。

## 8. 反馈循环：用户参与的"调教"

### 8.1 Swipe（左右滑动切换回复）

用户看到不满意的回复 → 滑动看下一个 → 选中最好的一个。

**活人感贡献**：用户参与了"哪些回复更像这个角色"的筛选，间接强化了角色一致性。虽然 LLM 不会学习，但用户通过选择保留的回复构建了更好的对话历史，后续生成会参考这些"被选中"的回复。

### 8.2 消息编辑

用户可以编辑角色的回复，修正不符合人设的部分。修正后的消息进入历史，成为后续生成的参考。

### 8.3 正则替换 (regex_scripts)

```json
{ "findRegex": "我是一个AI", "replaceString": "我是 Luna" }
```

角色卡级别的输出后处理，自动修正 LLM 的常见出戏行为。

## 9. 上下文注入的深度控制

### 深度 (depth) 的隐含语义

```
depth = 0   "紧急指令"    在最新消息之后，LLM 注意力最集中的位置
depth = 2-4 "近期状态"    在最近几轮对话中间，像"最近的心情"
depth = 8+  "背景信息"    深藏在历史中，像"一直存在但不突出的设定"
```

**活人感贡献**：不同信息有不同的"存在感"。核心人格用常驻条目 + 高 order，临时状态用 depth=0-2，背景知识用较深的 depth。这模拟了人类的注意力分配——眼前的事比背景更突出。

### depth + sticky 组合拳

```
条目: {
  keys: ["头疼"],
  content: "{{char}} 头疼，说话有气无力，偶尔揉太阳穴",
  sticky: 8,
  depth: 2
}
```

用户提到头疼 → 角色在接下来 8 轮中持续表现出头疼的状态 → 自然消退 → 不需要用户再提醒"你不是头疼吗"。

## 10. 综合分析：活人感的层次模型

```
Layer 5: 反馈循环 (swipe + 编辑 + 正则)
         用户参与筛选和修正，持续提升质量
              ↑
Layer 4: 社交动态 (群聊策略 + nudge)
         多角色场景中的行为差异化
              ↑
Layer 3: 状态演化 (变量 + delay + sticky/cooldown)
         角色有内部状态，状态随时间和事件变化
              ↑
Layer 2: 联想与记忆 (递归扫描 + 向量检索 + 摘要)
         一个话题带出相关记忆，长期记忆持久化
              ↑
Layer 1: 基础人格 (description + personality + mes_example + instruct)
         稳定的说话风格、性格特征、行为模式
              ↑
Layer 0: 时间与关系锚点 (时间宏 + Persona + 常驻 WI)
         角色知道自己是谁、对方是谁、现在是什么时候
```

**从下往上**：
- Layer 0-1 保证角色不"出戏"（基础一致性）
- Layer 2-3 让角色"有变化"（动态自然感）
- Layer 4-5 让角色"越来越像"（持续优化）

缺少任何一层都会削弱活人感：
- 没有 Layer 0：角色不知道自己是谁，开口就破功
- 没有 Layer 1：角色说话没辨识度，像通用 chatbot
- 没有 Layer 2：角色"金鱼记忆"，聊过的事转头就忘
- 没有 Layer 3：角色像 NPC，永远同一个状态
- 没有 Layer 4-5：角色偶尔出戏但无法修正，逐渐失真

## 对 hiPhone 项目的启发

### 1. 手机环境天然提供 Layer 0
hiPhone 项目的角色"住在手机里"，天然拥有：
- 时间感知（系统时钟）
- 用户身份（手机主人）
- 环境上下文（当前打开的 app、位置、电量、通知）

这比 SillyTavern 的宏系统丰富得多，应该充分利用。

### 2. App 状态可以充当 World Info 触发器
用户打开地图 app → 触发"出行相关"的 Lorebook 条目
用户打开音乐 app → 触发"音乐偏好"的记忆
用户收到日历提醒 → 角色可以主动提起

### 3. sticky/cooldown 的设备级实现
不需要做得和 SillyTavern 一样复杂。设备级的简化版：
- 状态持续 N 分钟（而不是 N 轮对话）
- 基于真实时间衰减（而不是消息计数）
- 结合手机的通知系统实现"主动想起"

### 4. 示例对话是性价比最高的投入
mes_example 几乎不需要代码支持，但对角色辨识度的贡献最大。hiPhone 的角色配置应该把示例对话作为**必填项**而不是可选项。

### 5. Persona 在手机场景中尤其重要
手机是私人设备，角色应该从一开始就知道用户的基本信息。建议在首次启动时引导用户填写 Persona，或者从手机数据（联系人名字、使用习惯）推断。

### 6. 正则替换是低成本的防出戏手段
角色卡附带几条正则规则，自动修正 LLM 的常见失误（自称 AI、使用真名、破坏第四面墙），性价比极高。
