# M4.1 — AI SDK 消费端 + XingYu 迁移

## 概述

本期交付两件事：

1. **AI 记忆层解耦** —— 平台新增 `characterMemoryStore`，成为 AI 上下文的唯一来源。和任何具体 App 解耦（XingYu 只是其中一个写入来源）
2. **`@hiphone/ai` SDK 消费端** —— user app 可以调纯 AI（`complete` / `streamComplete`）和角色对话（session-based，支持 `persistent=true`/`false` 两种语义）

**同期做的一次性深度改造**：**XingYu 完全迁入 SDK**。XingYu 不再直接调 `assemblePrompt` / `chatComplete` / `collectCharacterHistory`，而是作为 SDK 的第一个消费者运行 —— 这也验证了 SDK surface 的完整性。

**设计原则：** AI 是一个"人"，它有自己的记忆；任何 App（包括 XingYu）和 AI 对话都往这份记忆里加内容；summarizer 对记忆统一压缩，不感知来源。

## 本期做 / 不做

**做：**
- `src/platform/ai/characterMemoryStore.ts` —— 按角色的对话记忆流（带 `speakerId` + 原样 `content`），IDB 持久化
- `src/platform/userApp/sdk/ai.ts` —— `@hiphone/ai` 模块入口
- `complete` / `streamComplete` / `getCharacters` / `extractPlainText`
- `chatWithCharacter(charId, { persistent })` 返回 `ChatSession`；session 方法：`send` / `streamSend` / `append` / `replyToLast` / `streamReplyToLast` / `history` / `abort`
- `buildMemoryEntry(msg, source)` —— **只处理 user 侧富消息 → 文本占位**（`[图片 url]` / `[表情：desc]` / forward 平铺等）；assistant 的 raw JSON 原样进 memoryStore，不走 buildMemoryEntry
- `_appendMessage(msg, source)` —— 平台级 helper：同时写 xingYuDataStore.messages + memoryStore（含 quoteRef 展开等加工），强制所有 `setState({ messages: [...] })` 路径都用它
- `promptAssembly` 深度重构：**从 first-person labeled system block 改为 role alternation + name prefix**（`user: 小米：你好` 这种）；删除 `buildLabeledHistory` + `collectCharacterHistory`
- XingYu 所有写消息 action 走 `_appendMessage`；AI 回复路径改为通过 session（`mirror:false`，因为要自己做 parseReply 拆 bubble）
- `summarizer` 的触发/存储改成 character-level（条目挂在 memoryStore，不再挂 Conversation）
- **heartbeat 读写源迁移**（源码内部改动，不走 SDK）：`collectCharacterHistory` 替换为 memoryStore 读；`execSendMessage` / heartbeat_log 写入走 `_appendMessage`，source=`heartbeat`
- **`aiChatEngine.runAIChat` 写入源迁移**：和 XingYu 对齐走 `_appendMessage`（source=`xingyu`，因为对话在 XingYu UI 里展示）
- Demo user apps：`ai-translator-app`（`complete`）+ `ai-chat-app`（session）

**不做（明确推迟）：**
- 旧数据迁移 —— memoryStore 上线后从空开始；release note 标注"角色会失忆一次"
- **heartbeat 接入 SDK session / Tool Registry** —— 属 M4.2；本期 heartbeat 的 ReAct 协议、工具分发、agent 循环继续走现有 `chatComplete` + `assemblePrompt` 直接路径，只是数据源换了
- Multimodal 图片/音频送模型
- 速率限制 / token 预算
- 用户可见的"AI 记忆查看器" UI（Settings）—— 未来工作

## 用户需求

**来自对话的关键引述：**

> "AI的记忆不应该和可爱信耦合，可爱信只是一个聊天App，而AI是一个人。任何App和AI的交流都可以写入AI的记忆，然后AI也会自动对这些信息进行压缩。"

> "persistent: false 是有clone语义，但是clone的目的是为了多次聊天，这个是否有合理的sdk设计。"

> "本期目标是完成 AI SDK 和将 xingyu直接接入 AI SDK。"

## 关键决策

| # | 决策 | 选择 | 理由 |
|---|---|---|---|
| D1 | 记忆是角色级还是会话级 | **角色级**（characterMemoryStore[charId]） | "AI 是一个人"；角色有一份统一记忆，不按 conv 划分 |
| D2 | XingYu 与记忆层关系 | 双写：xingYuDataStore 存富消息（UI 用），memoryStore 存**原样交换文本**（AI 用） | 职责分离；memoryStore 只关心 LLM 原始交换的那份 |
| D3 | memoryStore content 形态 | **原样保真**：user 侧是输入文本 / 富消息占位（如 `[图片 url]`）；assistant 侧是 raw LLM output（含 JSON 结构化） | 保留 stickerId / signature action / 格式；模型看到的是自己上轮原 emit |
| D4 | 多方场景如何区分说话人 | MemoryEntry 增加 `speakerId`；render 时按 role + 名字前缀组织（`user: 小月：...`） | role=assistant 永远是本角色自己；role=user 可能是玩家 / 其它 AI，靠前缀区分 |
| D5 | 旧数据迁移 | **不迁移** | 简化实现；接受 "AI 失忆一次" 的 UX 影响 |
| D6 | `persistent:false` 语义 | Clone 快照 + session 内部多轮累积 | 用户明确要求"clone 目的是多次聊天"；不要求 caller 手动维护 messages |
| D7 | Session 的形状 | 一个 JS object，`send` / `streamSend` / `append` / `replyToLast` / `streamReplyToLast` / `history` / `abort` | 能覆盖 XingYu 所有现有 AI 触发路径（文本 + 图/贴/转发后触发回复） |
| D8 | 回复落 memoryStore 的原子性 | user msg 先写；AI 回复仅在完成后写（abort/错误时不写 partial） | 避免"半句话"污染记忆；caller 想留 partial 用 `append` 显式 |
| D9 | AI 未配置的错误 | SDK 抛 `AIUnavailableError`；caller 处理 | SDK 通用；XingYu 在调用处 catch 并 fallback 到 `IDOL_REPLY_POOL` |
| D10 | heartbeat 接入策略 | 本期**只换数据源**（读 memoryStore、写走 `_appendMessage`）；SDK / Tool Registry 接入留给 M4.2 | ReAct 和 tool 分发是 M4.2 整体升级范畴；本期硬塞会扭曲 session API |
| D11 | `aiChatEngine.runAIChat`（AI-AI 对话）迁不迁 | **内部写入迁**（走 `_appendMessage`），**调用路径不变**（不走 session） | 和 heartbeat 同理；本期只求数据一致，不求代码路径统一 |
| D12 | 压缩粒度 | character-level（不再 per-conv） | 和 D1 对齐；压缩结果是一条 MemoryEntry |
| D13 | Sandbox → memoryStore 的写权限 | 只通过 session 写；不暴露裸 memoryStore API 给 user app | 隐藏实现；caller 可见面是 session，不是 store |
| D14 | prompt format | **role alternation + name prefix**（取代现有 first-person labeled system block） | 和 OpenAI/Anthropic/DeepSeek API 主流格式对齐；raw JSON assistant 可以直接原样塞进 role=assistant；KV cache 粒度更细；render 代码量小一半 |

## 架构

### 1. `characterMemoryStore`（平台层）

位置：`src/platform/ai/characterMemoryStore.ts`

```ts
export interface MemoryEntry {
  id: string;                    // uid
  characterId: string;           // 这条 entry 挂在谁的记忆上
  role: 'user' | 'assistant' | 'system';
                                 // 相对 characterId 的视角：
                                 //   assistant = characterId 自己说的
                                 //   user      = 外界输入（玩家 or 其它 AI）
                                 //   system    = summarizer 摘要 / 系统事件
  speakerId: string;             // 真正说话人
                                 //   'me'        → 玩家 persona
                                 //   'char-xxx'  → 某个角色
                                 //   'system'    → 系统（压缩摘要等）
  content: string;               // 原样保真：
                                 //   - user:      文本（含富消息占位 `[图片 url]` / `[表情：desc]` 等；多个 user 如果来自 XingYu 则已展开 quoteRef / forward_card）
                                 //   - assistant: raw LLM output（XingYu 场景是 JSON 字符串；user app 可能是 plain text）
                                 //   - system:    摘要文本 / 系统事件文本
                                 // 说话人名字前缀（"小米：..."）由 render 层加，不存在 content 里
  source:
    | 'xingyu'                   // XingYu 的 UI 写入镜像（双写来的）
    | `app:${string}`            // user app 通过 session 写入
    | 'heartbeat'                // heartbeat 工具写入（`execSendMessage`、heartbeat_log、AI-AI 产物等）
    | 'system';                  // summarizer 压缩结果、系统事件
  createdAt: number;             // Date.now()
  compressed?: true;             // 是否是 summarizer 生成的压缩摘要条目
}

export interface CharacterMemoryState {
  entries: Record<string, MemoryEntry[]>;   // charId → 按 createdAt 升序

  append: (charId: string, entry: Omit<MemoryEntry, 'id' | 'characterId' | 'createdAt'>) => MemoryEntry;
  batchAppend: (charId: string, entries: Omit<MemoryEntry, 'id' | 'characterId' | 'createdAt'>[]) => MemoryEntry[];
  getAll: (charId: string) => readonly MemoryEntry[];
  getSnapshot: (charId: string) => readonly MemoryEntry[];   // 不可变拷贝（给 session 快照用）
  replaceRange: (charId: string, startId: string, endId: string, summary: MemoryEntry) => void;   // summarizer 用
  clear: (charId: string) => void;                           // 未来"AI 记忆查看器"用
}
```

**持久化：** IDB 通过 `idbRecordStorage`（和 xingYuDataStore.messages 同类型的 record store，按 entry 追加）。重启时从 IDB 恢复 `entries`。

**线程安全：** 所有写入走 Zustand action，单线程同步；并发 `append` 按调用顺序序列化。

**AI-AI 的跨角色写入（M4.1 已支持，由 `_appendMessage` 间接触发）：** 当 aiChatEngine 写一条 AI-A → AI-B 的对话消息时，同一 raw content 会以不同 role 分别 append 到两个 character 的 memoryStore：
- A 的 memoryStore：`{ characterId:'char-a', role:'assistant', speakerId:'char-a', content:raw }`
- B 的 memoryStore：`{ characterId:'char-b', role:'user',      speakerId:'char-a', content:raw }`
这样每个角色从自己视角读到的都是连贯的"我 vs 外界"，不需要 render 时猜。

### 2. `@hiphone/ai` SDK 表面

位置：`src/platform/userApp/sdk/ai.ts`

```ts
// ─── Level 1: 纯 AI ────────────────────────────────────────
export interface Message { role: 'system' | 'user' | 'assistant'; content: string }
export interface CompletionOptions { temperature?: number }

export function complete(
  messages: Message[],
  opts?: CompletionOptions,
): Promise<string>

export function streamComplete(
  messages: Message[],
  opts?: CompletionOptions & { signal?: AbortSignal },
): AsyncIterable<string>

// ─── Level 2: 角色会话 ────────────────────────────────────
export interface ChatOptions { persistent?: boolean; signal?: AbortSignal }

export function chatWithCharacter(
  characterId: string,
  options?: ChatOptions,
): ChatSession

export interface SessionEntry {
  role: 'user' | 'assistant'   // 相对 session.characterId 的视角
  speakerId: string            // 'me' | 'char-xxx'；简单 user app 可忽略（自己说话时固定为 'me'）
  content: string              // 原样（user 是文本 / 富消息占位；assistant 可能是 raw JSON）
  timestamp: number
}

/**
 * 双写控制选项。只在 persistent=true 的 session 上有效。
 * - mirror=true (default): SDK 自动把这次操作涉及的 user/assistant 内容写入 memoryStore
 * - mirror=false: SDK 仅更新 session buffer；写 memoryStore 由 caller 自己负责
 * 
 * 场景：XingYu 内部流程已经自己往 memoryStore 写过一次（因为富消息要做 buildMemoryEntry），
 * 所以它调 session 时传 mirror=false 避免重复写入。user app 永远用默认 true。
 */
export interface MirrorOption { mirror?: boolean }

export interface ChatSession {
  readonly characterId: string
  readonly persistent: boolean
  readonly history: readonly SessionEntry[]

  send(content: string, opts?: MirrorOption): Promise<string>
  streamSend(content: string, opts?: MirrorOption): AsyncIterable<string>

  append(
    entry: { role: 'user' | 'assistant'; content: string; speakerId?: string },
    opts?: MirrorOption,
  ): void
  //   speakerId 默认：
  //     role='user'      → 'me'（user app 是玩家自己；XingYu mirror=false 时显式传入）
  //     role='assistant' → session.characterId（自己）

  replyToLast(opts?: MirrorOption): Promise<string>
  streamReplyToLast(opts?: MirrorOption): AsyncIterable<string>

  abort(): void
}

// ─── Level 3: 查角色 ──────────────────────────────────────
export interface CharacterInfo {
  id: string
  name: string
  avatar: string
  description: string
}

export function getCharacters(): CharacterInfo[]

// ─── 辅助 ─────────────────────────────────────────────────
/**
 * 从 raw LLM output 提取纯文本（忽略 sticker/signature/其它结构化 item）。
 * - 如果 raw 是 XingYu-style JSON array，把所有 type:'text' 的 content 按顺序拼起来
 * - 如果 raw parse 失败（plain text LLM 输出），原样返回
 * user app 一般用 await extractPlainText(await s.send('...')) 消费角色回复。
 */
export function extractPlainText(raw: string): string

// ─── 异常 ─────────────────────────────────────────────────
export class AIUnavailableError extends Error {}         // provider 未配置
export class AICharacterNotFoundError extends Error {}   // charId 无效
export class AIAbortedError extends Error {}             // session.abort() 之后被 await 的 promise
```

### 3. Session 行为细节

#### 3.1 创建

- 同步 capture 当前 appId（`getCurrentAppId()`）作为 `source=app:<id>`
- 校验 `characterId` 在 characterStore 中存在；否则抛 `AICharacterNotFoundError`
- 若 `persistent: false` —— 调 `memoryStore.getSnapshot(charId)` 拍一份快照到 session 私有字段
- 若 `persistent: true` —— 不拍快照；每次调用前读 memoryStore 最新版本

#### 3.2 `send(content)` / `streamSend(content)`

```
prompt = assemblePrompt({
  character: characterStore[charId],
  persona: personaStore.active,
  aiConfig: aiConfigStore,
  chatHistory: historyForSession(),   // 下方 3.6 解释
  newUserMessage: content,            // 和 caller appId 对应的前缀由 assemblePrompt 内部 render 加
})
→ chatComplete(stream)
→ if persistent && mirror:
    memoryStore.append(charId, {
      role: 'user', speakerId: 'me',
      content, source: `app:<callerAppId>`,
    })
    await full reply
    memoryStore.append(charId, {
      role: 'assistant', speakerId: charId,
      content: rawReply, source: `app:<callerAppId>`,
    })
  else:
    session._buffer.push(user + assistant entries with same speakerId rules)
→ return rawReply / yield tokens
```

**abort 处理：** `streamSend` 过程中 `session.abort()` 被调用：
- user msg 已入库（persistent=true 场景）/ 入 session buffer（persistent=false）
- 已 yield 的 token 保留在 caller
- 未完成的 AI reply 不写入 memoryStore / session buffer
- 已 yield 的 AsyncIterable 停止产出，抛 `AIAbortedError`

#### 3.3 `append(entry)`

同步 push 到 session buffer；persistent=true 同时调 `memoryStore.append()`。**不触发 AI 调用。** 用于：
- XingYu `sendImageMessage` —— 先 `append({ role:'user', content:'[图片 <url>]' })` 然后 `streamReplyToLast()`
- caller 想塞一条 system note（目前不支持 role:'system'，reserved）

#### 3.4 `replyToLast(content)` / `streamReplyToLast(content)`

对当前 session state + memoryStore 上下文调 AI；回复按 persistent 规则落。不接受 user content（因为已经 append 过了）。

#### 3.5 `abort()`

取消当前 in-flight stream（AbortController）。不重置 session 状态。

#### 3.6 `historyForSession()` —— 内部辅助

- persistent=true：返回 `memoryStore.getAll(charId)` + session buffer 里还没入库的 entries（理论上是空，但如果 append 了一条但 replyToLast 还没发起时可能有）
- persistent=false：返回初始快照 + session buffer

### 4. 回复落 memoryStore 规则（完整表）

表中行为默认 `mirror: true`（用户 app 的默认）。**`mirror: false` 时这一整列 memoryStore 写入全部跳过**，只更新 session buffer —— caller 自己负责写。

| Session 方法 | persistent | 写 user msg | 写 AI 回复 |
|---|---|---|---|
| `send` / `streamSend(text)` | true | ✅ memoryStore, role=user, source=`app:<id>` | ✅ memoryStore, role=assistant |
| `send` / `streamSend(text)` | false | ❌ 仅 session buffer | ❌ 仅 session buffer |
| `append({ role, content })` | true | ✅ memoryStore, 按 role | — |
| `append({ role, content })` | false | ❌ 仅 session buffer | — |
| `replyToLast` / `streamReplyToLast` | true | — | ✅ memoryStore |
| `replyToLast` / `streamReplyToLast` | false | — | ❌ 仅 session buffer |
| abort (所有方法) | — | 已入库的 user msg 保留 | 未完成 reply 整条不写（无 partial 污染） |

**mirror=false 的唯一当前消费者：XingYu**。它在 §8.1 的流程里自己按"raw reply 一整条，不按 bubble 拆分"的规则写 memoryStore，是 SDK 没法替它做的。

### 5. `promptAssembly` 深度重构

#### 5.1 format 从 "first-person labeled system block" 改为 "role alternation + name prefix"

**当前架构（要删）：**
- `buildLabeledHistory` 把所有历史消息塞成一个 `system` role 的大文本块：`[对话记录]\n[14:30] 小米：xxx\n[14:30] 我：yyy\n...`
- 末尾最后一条非自己的消息被复制出来作为 `user` role 用于触发
- 副作用：多条 assistant 消息被拆平成 labeled narration；JSON 结构化信息丢失；stickerId / signature 动作无法复现

**M4.1 架构：**
- 直接 role alternation：每个 MemoryEntry 独立成 OpenAI-style `{ role, content }`
- user role content 前缀：**说话人名字** + `：` + entry.content，区分多方
- assistant role content：**原样**（XingYu 场景就是 raw JSON；user app 场景是 plain text）
- system role：character card + world book + format 指令（稳定，不变）
- post-history role=system：device context + time（每次变；放最后）

#### 5.2 render 算法（替换 `buildLabeledHistory` + `messageToContent`）

```ts
// src/platform/ai/promptAssembly.ts 新内部函数
function renderMemoryToChatMessages(
  entries: readonly MemoryEntry[],
  ctx: {
    charactersById: Map<string, Character>;
    personaName: string;
    currentCharId: string;
  },
): ChatMessage[] {
  const result: ChatMessage[] = [];
  for (const e of entries) {
    if (e.role === 'system') {
      // summarizer compressed entry
      result.push({ role: 'system', content: e.content });
      continue;
    }
    if (e.role === 'assistant') {
      // 原样；assistant 永远是 currentCharId 自己
      result.push({ role: 'assistant', content: e.content });
      continue;
    }
    // role === 'user' — 用 speakerId 查名字，前缀进 content
    const name = resolveSpeakerName(e.speakerId, ctx);
    result.push({ role: 'user', content: `${name}：${e.content}` });
  }
  return result;
}

function resolveSpeakerName(
  speakerId: string,
  ctx: { charactersById: Map<string, Character>; personaName: string },
): string {
  if (speakerId === 'me') return ctx.personaName;
  if (speakerId.startsWith('char-')) {
    const charId = speakerId.slice(5);
    return ctx.charactersById.get(charId)?.name ?? speakerId;
  }
  return speakerId;
}
```

### 6. `buildMemoryEntry` —— user 侧富消息 → 文本

**只管 user 侧写入的富消息**（XingYu 的 `sendImageMessage` / `sendStickerMessage` / `sendForwardCardMessage` 等）。assistant raw JSON 不过这里，直接 append 到 memoryStore。

```ts
// src/platform/ai/buildMemoryEntry.ts
export function buildMemoryEntry(
  msg: Message,                           // xingYuDataStore.Message（文本/图/贴纸/转发/心跳日志）
  source: MemoryEntry['source'],
  ctx: { charactersById: Map<string, Character>; personaName: string; userNickname: string },
): Omit<MemoryEntry, 'id' | 'characterId' | 'createdAt'> | null
```

**输出 `content` 的加工规则**（从现有 `messageToContent` + `collectCharacterHistory` 的 quoteRef 展开合并过来）：

| msg.type | content 规则 |
|---|---|
| `text` | `msg.text`；有 `quoteRef` 时前置 `[引用 <name>：<preview>] ` |
| `image` | `[图片 <imageUrl>]`（不做 multimodal，vision 模式未来单独考虑） |
| `sticker` | `[表情：<stickerDesc>]` |
| `forward_card` | `[转发的聊天记录：<title>]\n- X：...\n[/转发结束]`（同现有平铺逻辑） |
| `heartbeat_log` | `[自主活动记录]\n<text>` |
| error message（`[AI 回复失败]` / `[未配置 AI 服务]` 开头） | **return `null`**（不入记忆，同现有行为） |

输出 `role` / `speakerId`：
- `msg.senderId === 'me'` → `role='user'`, `speakerId='me'`
- `msg.senderId` 以 `char-` 开头且 === currentCharId → `role='assistant'`, `speakerId=currentCharId`
- 其它 `char-xxx`（观摩到的第三方）→ `role='user'`, `speakerId=msg.senderId`（注意 role 仍是 user，因为对 currentCharId 而言是外界输入）

**调用点：** 由 `_appendMessage(msg, source)` helper 统一调（见 §8.0）。

### 7. `_appendMessage(msg, source)` —— 统一双写 helper

**位置：** `src/apps/XingYu/xingYuDataStore.ts` 顶层或 `src/platform/ai/memoryWriter.ts`（二选一；推荐后者以便 heartbeat / aiChat 清晰引用）

```ts
// 所有会往 xingYuDataStore.messages[] 追加消息的代码必须走这个 helper
// 效果：在一个 Zustand state update 里同时写 xingYuDataStore 和 memoryStore
export function _appendMessage(msg: Message, source: MemoryEntry['source']): void {
  // 1. 写 xingYuDataStore.messages 和 conversations.lastMsg/lastTime/unread
  const xy = useXYData.getState();
  useXYData.setState({
    messages: [...xy.messages, msg],
    conversations: xy.conversations.map((c) =>
      c.id === msg.convId
        ? { ...c, lastMsg: derivePreview(msg), lastTime: msg.timestamp,
            unread: shouldIncrementUnread(msg, c) ? c.unread + 1 : c.unread }
        : c,
    ),
  });

  // 2. 推 memoryStore（若能解析出 characterId）
  const characterId = deriveCharacterIdFromConv(msg.convId);   // c-char-<id> → <id>
  if (!characterId) return;

  const entry = buildMemoryEntry(msg, source, buildRenderCtx(characterId));
  if (entry) {
    useCharacterMemory.getState().append(characterId, entry);
  }

  // 3. 对于 AI-AI convs：若 conv.aiChatParticipants 包含多个角色，需要跨角色写
  const conv = useXYData.getState().conversations.find((c) => c.id === msg.convId);
  if (conv?.aiChatParticipants?.length) {
    for (const otherId of conv.aiChatParticipants) {
      if (otherId === characterId) continue;
      // 以 otherId 视角：msg.senderId 如果是 otherId 则 role=assistant, 否则 role=user
      const entryForOther = buildMemoryEntry(msg, source, buildRenderCtx(otherId));
      if (entryForOther) {
        useCharacterMemory.getState().append(otherId, entryForOther);
      }
    }
  }
}
```

**调用契约：所有会向 `xingYuDataStore.messages[]` append 的地方必须用这个 helper。**

### 8. Summarizer 改造

- **粒度从 conv-level 改为 character-level**：压缩目标是 `memoryStore.entries[charId]`
- 触发点：任何 `memoryStore.append` 之后检查该角色总 entries 的 token 数是否超过阈值 `summarizeThreshold × contextWindow`
- 压缩窗口：最旧的一批到 `entries.length - keepRecentMessages` 之间（不包含 already-compressed 条目）
- 结果：一条 `role: 'system', compressed: true, content: summary, source: 'system'` 的 MemoryEntry 替换被压缩的条目，通过 `memoryStore.replaceRange()` 完成
- Conversation schema 的 `summary` / `summaryUpToTimestamp` 字段 —— **删除**；迁移路径：启动时若还有残留不做处理（让它自然失效，因为 promptAssembly 不再读）

## XingYu 迁移（详细对照）

**写入侧统一走 `_appendMessage(msg, source)`**（§7）—— 它内部双写 xingYuDataStore + memoryStore。XingYu 的 action 只关心富消息，不感知 memoryStore。

**AI 调用侧**走 session API（`{ mirror: false }`，因为 XingYu 要 parseReply + filterReply，raw reply 的写入时机不是 session 能决定的）。

### 9.1 文本消息：`sendMessage(convId, text, quoteRef?)`

```
1. _appendMessage({ type:'text', text, quoteRef, senderId:'me', convId, ts }, 'xingyu')
   → xingYuDataStore.messages += [新消息]；memoryStore(charId) += {role:'user', speakerId:'me', content:加工后文本}
   
2. const session = chatWithCharacter(charId, { persistent: true })   // 每次发消息一个新 session
3. let rawReply = ''
4. for await (const tok of session.streamReplyToLast({ mirror: false })) rawReply += tok
   → session 内部从 memoryStore 拉最新历史做 prompt；不写入 memoryStore（mirror=false）
   
5. const filtered = filterReply(rawReply)
6. const bubbles = parseReply(filtered)
7. for each bubble:
     _appendMessage(bubbleMsg, 'xingyu')   // 300-800ms 间隔投递
     
8. 在所有 bubble 投递完成后，追加一条 memoryStore assistant 条目：
     memoryStore.append(charId, { role:'assistant', speakerId:charId, content: rawReply, source:'xingyu' })
   
   ⚠️ 这里是有意绕过 _appendMessage —— 因为 memoryStore 要的是"raw JSON 一整条"，但
   xingYuDataStore 已经装了拆分后的 bubbles，直接写 memoryStore 只需要一次。
```

**为什么 step 8 不走 `_appendMessage`？** `_appendMessage` 每条 bubble 都会在 memoryStore 写一条，会把 raw JSON 拆平 —— 那就违反 D3"原样保真"决策。所以 XingYu 的 assistant reply 写 memoryStore 是**一次 raw，一次**，单独调 `memoryStore.append` 而不走 helper。

**mechanism 层总结：**
- user 侧所有富消息都走 `_appendMessage`（正常双写）
- assistant 侧（AI 回复）走 session + 手动 `memoryStore.append(raw)`（不能走 helper）

| `sendStickerMessage(convId, url, desc)` | 同上，_appendMessage 的 msg.type='sticker' |
| `sendForwardCardMessage(...)` | 同上，msg.type='forward_card' |
