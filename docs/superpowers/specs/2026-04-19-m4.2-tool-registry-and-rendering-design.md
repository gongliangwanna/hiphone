# M4.2 — Tool Registry + Reply Renderer + App Context Events

## 概述

M4.1 做完后，user app 通过 `@hiphone/ai` session 能调 AI，但所有 app 被迫套 XingYu 的 JSON 回复格式（`text` / `sticker` / `signature`）、memoryStore 存 raw JSON、跨 app 历史会诱导模型乱 emit 失效工具。

本期把 AI 交互架构重构为三条正交能力 —— **Tool Registry + Reply Renderer Registry + App Context Events** —— 每个 app 注册自己的能力，平台层负责拼 prompt、render 成 memory、管理 app 切换。

**核心原则：**
- memoryStore content 永远是**自然文本**，不是 raw JSON
- 从 raw → memory 的转换经过 **app 注册的 renderer**，renderer 必须无损保留决策相关信息（stickerId / action params）
- app 侧需要做 AI 集成，**只要注册 3 样东西**：tools、renderer、appSystemPrompt 函数
- chunks 6.5 / 7 / 8 从这三个注册点**自动派生**，app 不再手写 prompt 模板
- app 之间的上下文边界通过**自动注入 system marker**（切换时）+ **可选的 `injectSystemEvent`** API（高频变化时）清晰化

## 本期做 / 不做

**做：**

- `src/platform/ai/toolRegistry.ts` —— 平台 Tool Registry；`registerTools(appId, defs[])`、`getTools(appId)`、`unregisterApp(appId)`
- `src/platform/ai/replyRendererRegistry.ts` —— 平台 Reply Renderer Registry；`registerReplyRenderer(appId, renderer)`、`getReplyRenderer(appId)`（默认 XingYu renderer）
- `src/platform/ai/appSystemPromptRegistry.ts` —— 平台 appSystemPrompt 函数注册；`registerAppSystemPrompt(appId, () => string)`、`getAppSystemPrompt(appId)`
- `src/platform/ai/characterAppState.ts` —— 角色的 `lastActiveAppId`，session 创建时检测 + 注入 app-switch system marker
- `src/platform/ai/contextEvents.ts` —— `injectSystemEvent(charId, message)` 一次性系统事件 API
- `src/platform/userApp/sdk/ai.ts` 扩展 —— 暴露 `registerTools` / `registerReplyRenderer` / `registerAppSystemPrompt` / `injectSystemEvent`
- `promptAssembly` 改造 —— chunks 6.5（appSystemPrompt 快照）/ 7（统一回复格式，二分 `text` 和 `action`）/ 8（Tool 清单）
- **memoryStore.MemoryEntry.content 语义变更** —— 现在存 **rendered 自然文本**（assistant 端），不再存 raw JSON
- `ChatSession.send` 返回类型扩展为 `ChatReply { raw, rendered, items, actions, text }`
- `parseReply` 支持统一 `{ type: 'text' | 'action' }` item shape；保留 `sticker` / `signature` 的 legacy dispatch 到 XingYu 的 registered action name
- XingYu 迁移 —— `sticker` / `update_signature` 注册为 XingYu 的 tool；不再是特殊 type；stickerStore 的变化通过 `registerAppSystemPrompt('xingyu', () => stickers...)` 动态注入
- Demo fixture `ai-auction-app`（拍卖师）—— 验证非 XingYu 格式 app 的端到端

**不做（明确推迟）：**

- **Provider-native tool calling**（OpenAI function calling / Anthropic `tool_use`）—— 本期仍走 prompt-describe + parse；native 接入在 M4.3+
- **heartbeat 迁入**—— heartbeat 是 agent 场景，需要 tool-result feedback loop（错误回灌给模型），不在本期范围；继续走 ReAct prompt-parsing，但需**只改数据源**（读 memoryStore，不改 agent 逻辑）
- **Settings 的 AI 工具管理 UI**（per-app / per-tool 开关）—— 留给 M4.3
- **Agent 模式的 tool-result 回灌**
- **动态工具加载 / 卸载中途**（session 活着期间改变 tools 不支持 —— 要重建 session）
- Remote store / AI App Builder（留给后续 milestone）

## 用户需求（对话原文截取）

> "非 AGENT 场景 AI 都会以 json 数组的方式回复,而回写到上下文时,需要有 render 机制将其 render 为自然文本... 使用我们 SDK 必须支持要添加渲染器注册."

> "对于 stickerId 信息保留的问题,我们可以在规范中要求 render 务必将信息都 render 到 mem 中,不要丢失信息即可."

> "chunks 7,8 我们 app 注册好 tool, 那么这里就通过 tool 信息生成即可.不需要 app 来自行设置."

> "appSystemPrompt, app 应该提供的是一个函数,而非接口,因为比如表情包列表,可以动态变更."

> "对于变化频率非常快的,应建议不放在 appSystemPrompt,而是提供能力支持发系统消息."

> "角色需要存储一个当前在使用的 app,一开始为空. 然后如果 app 发生变换, AI 会收到这个变换通知."

## 关键决策

| # | 决策 | 选择 | 理由 |
|---|---|---|---|
| D1 | memoryStore content 存什么 | **render 后的自然文本**（不是 raw JSON）；assistant 端经过 app-specific renderer 转换 | token 效率 + 跨 app 去格式化污染 + prompt 可读性。之前 M4.1 "存 raw 让 model 看自己上轮 emit" 的 KV cache 理由被重新评估：现代模型 instruction following 足够强，format drift 风险低于跨 app 污染风险 |
| D2 | renderer 无损原则 | 写进 spec 的硬性规范 —— renderer MUST preserve all decision-relevant info into memory text | stickerId / action params 是未来同一场景内连续决策的依据。例：`[表情 s1: 笑]` 而非 `[发了个笑脸]` |
| D3 | renderer 注册时机 | 懒注册：app mount / top-level 调 `registerReplyRenderer(appId, ...)`；写入 memory 时查。未注册落到 XingYu 默认 renderer | 和 Service Registry 一致；避免 installer 阶段对 renderer 硬依赖 |
| D4 | appSystemPrompt 的类型 | **函数 `() => string`**，session 创建时调一次 freeze | 支持动态内容（表情包列表变化）。比 string 更灵活，比每轮重调更 cache 友好 |
| D5 | chunks 7/8 形态 | 从 Tool Registry **自动派生**，app 不再手写 replyFormat 模板 | app 注册 tools 是唯一事实源；prompt 层派生无歧义 |
| D6 | 回复格式的统一 | 所有 app 输出 `{type:'text'\|'action'}` 二分结构；sticker / signature / 任何自定义 action 都走 `{type:'action',name,params}` | 简化 parseReply；XingYu 原有的 sticker/signature 改造为 tool；UI 按 `action.name` dispatch |
| D7 | 高频动态状态怎么进 context | `injectSystemEvent(charId, message)` 一次性系统事件，写 memoryStore 的 `role:'system'` 条目 | 与 appSystemPrompt 分工明确：slow→prompt，fast→event |
| D8 | app 切换边界 | 每角色维护 `lastActiveAppId`，session 创建时若当前 appId 变化，自动注入 `[上下文切换]` system entry | 让 AI 显式看到"从 A 切到 B"，理解工具集变化 |
| D9 | heartbeat 迁不迁 | **不迁**（agent 场景，需 tool error feedback loop） | 本期 Q&A 场景不需要 error 回灌；heartbeat 是 M4.3/agent-mode 的范畴 |
| D10 | provider-native tool calling | **不做**；继续 prompt-describe | native 接入需 per-provider 适配；M4.3+ 单独处理 |
| D11 | Tool Registry 是否复用 Service Registry | **不复用**（独立表）；两者用途不同：Service 是 app-to-app RPC，Tool 是 AI-facing 动作 | 清晰分层；未来 ecosystem 里一个 app 可能同时既 register service 也 register tool，但作用对象不同 |

## 架构

### 1. 三个注册表（平台层）

```ts
// src/platform/ai/toolRegistry.ts
export interface ToolDefinition {
  name: string;
  description: string;
  parameters: Record<string, string>;   // { paramName: typeHint } 简化 JSON-Schema-lite
}

export function registerTools(appId: string, tools: ToolDefinition[]): void;
export function getTools(appId: string): ToolDefinition[];   // 未注册返回 []
export function unregisterApp(appId: string): void;          // installer.uninstall 调用

// src/platform/ai/replyRendererRegistry.ts
export interface ReplyRenderContext {
  speakerName: string;          // 本轮说话的角色显示名
  tools: ToolDefinition[];      // session 当前 app 的 tool 清单
}

export interface ReplyRenderer {
  render(raw: string, ctx: ReplyRenderContext): string;
}

export function registerReplyRenderer(appId: string, renderer: ReplyRenderer): void;
export function getReplyRenderer(appId: string): ReplyRenderer;   // 未注册返回 DEFAULT_XINGYU_RENDERER

// src/platform/ai/appSystemPromptRegistry.ts
export function registerAppSystemPrompt(appId: string, fn: () => string): void;
export function getAppSystemPrompt(appId: string): (() => string) | null;
```

**持久化：** 三个 registry 都是 module-level Map（in-memory），重启后 app 重新注册。不入 IDB。

**卸载清理：** installer.uninstall 同步调 `toolRegistry.unregisterApp` / `replyRendererRegistry.unregisterApp` / `appSystemPromptRegistry.unregisterApp`。

### 2. 默认 XingYu Renderer 的无损规范实现

```ts
// src/platform/ai/defaultXingYuRenderer.ts
export const defaultXingYuRenderer: ReplyRenderer = {
  render(raw, ctx) {
    const items = parseReply(raw);
    const lines: string[] = [];
    for (const item of items) {
      if (item.type === 'text') {
        lines.push(`${ctx.speakerName}: ${item.content}`);
        continue;
      }
      if (item.type === 'action') {
        // 统一格式：`名字(参数)`，参数按 "k=v" 排列
        const paramPairs = Object.entries(item.params ?? {})
          .map(([k, v]) => `${k}=${typeof v === 'string' ? v : JSON.stringify(v)}`)
          .join(' ');
        lines.push(`${ctx.speakerName}: 【${item.name}】${paramPairs}`);
        continue;
      }
      // legacy sticker/signature，M4.2 迁移后 XingYu 改成 action 形态，但
      // 过渡期保留兼容
      if (item.type === 'sticker') {
        lines.push(`${ctx.speakerName}: [表情 ${item.stickerId}: ${item.content}]`);
      } else if (item.type === 'signature') {
        lines.push(`${ctx.speakerName}: [更新签名: ${item.text}]`);
      }
    }
    return lines.join('\n');
  },
};
```

function openSession(charId: string, opts: ChatOptions): ChatSession {
  const currentAppId = getCurrentAppId();
  const lastAppId = getLastActiveAppId(charId);

  if (lastAppId !== currentAppId) {
    const currentName = getAppName(currentAppId) ?? currentAppId;
    const fromName = lastAppId ? (getAppName(lastAppId) ?? lastAppId) : null;
    const message = fromName

    setLastActiveAppId(charId, currentAppId);
  }

  // ... 继续创建 session
}

### 5. Chunks 6.5 / 7 / 8 的生成

#### 6.5 [当前任务]

```ts
function buildAppSystemPromptChunk(currentAppId: string): string | null {
  const fn = getAppSystemPrompt(currentAppId);
  if (!fn) return null;
  const snapshot = fn();
  if (!snapshot.trim()) return null;
  return `[当前任务]\n${snapshot}`;
}
```

**空字符串 / 未注册 → 整个 chunk 不出现在 prompt 里**（不引入 `[当前任务]` 空标题）。

#### 7 [回复格式] — 统一模板

```
你用 JSON 数组回复，每条消息是以下两类之一：

1. 叙述 / 对白:
   {"type":"text","content":"..."}

2. 执行动作:
   {"type":"action","name":"<动作名>","params":{...}}

示例：
[{"type":"text","content":"欢迎"},{"type":"action","name":"<动作>","params":{...}}]

只输出 JSON 数组，不要其他内容。
```

**模板不随 app 变**（structural stability）。app-specific 的动作名 / 参数只在 chunk 8 出现。

#### 8 [可用动作] — Tool Registry 派生

```ts
function buildToolsChunk(tools: ToolDefinition[]): string | null {
  if (tools.length === 0) return null;
  const lines = tools.map((t) => {
    const params = Object.entries(t.parameters)
      .map(([k, v]) => `${k}: ${v}`)
      .join(', ');
    return `- ${t.name}: ${t.description}\n  参数: { ${params} }`;
  });
  return `[可用动作]\n${lines.join('\n')}`;
}
```

**无 tool 注册 → chunk 8 不出现**。session 只有 text 输出（但 [回复格式] 模板仍然允许 action 形式 —— 模型看不到 action 清单就不会用）。

### 6. ChatSession 返回结构升级

```ts
// @hiphone/ai
export interface ReplyItemText { type: 'text'; content: string }
export interface ReplyItemAction { type: 'action'; name: string; params: Record<string, unknown> }
// Legacy 兼容（XingYu 过渡期）
export interface ReplyItemSticker { type: 'sticker'; stickerId: string; content: string }
export interface ReplyItemSignature { type: 'signature'; text: string }

export type ReplyItem =
  | ReplyItemText
  | ReplyItemAction
  | ReplyItemSticker
  | ReplyItemSignature;

export interface ChatReply {
  raw: string;                // LLM 原 JSON（给 app 做 UI 解析）
  rendered: string;           // renderer 输出（memoryStore 里存的那份）
  items: ReplyItem[];         // parseReply 拆好的
  actions: ReplyItemAction[]; // items.filter(i => i.type === 'action')
  text: string;               // text items 拼的纯文本（便捷字段）
}

// Session 主方法签名
send(content: string, opts?: MirrorOption): Promise<ChatReply>
streamSend(content: string, opts?: MirrorOption): AsyncIterable<string>  // 仍是 raw token
replyToLast(opts?: MirrorOption): Promise<ChatReply>
streamReplyToLast(opts?: MirrorOption): AsyncIterable<string>
```

streaming 拿的还是 raw token（LLM 生成的字符流）。用户需要 rendered 文本时等流结束后取最终 session.history 最后一项（buffer 里 content 已 rendered）或者直接 `await send()` 拿 `ChatReply`。

### 7. memoryStore content 语义变更

```
M4.1 (current):
  user entry:      content = 'hello'                              (plain text)
  assistant entry: content = '[{"type":"text","content":"hi"}]'   (raw JSON)
  system entry:    content = '[之前的对话摘要] ...'                  (text)

M4.2:
  user entry:      content = 'hello'                              (不变)
  assistant entry: content = '我: hi'                              (rendered 自然文本)  ← 变
  system entry:    content = '[上下文切换] ...' / '[表情包] ...'    (含新类型的系统事件)
```

**迁移：不做一次性迁移**。M4.1 时已经定了"不迁老数据"。M4.2 上线后所有新的 assistant entry 都走新 render 路径。

### 9. XingYu 迁移

XingYu 在 `registerBuiltins.ts` 里（或 XingYu 的 init module）：

```ts
registerTools('xingyu', [
  {
    name: 'sticker',
    description: '发一个表情包',
    parameters: { stickerId: 'string', content: 'string (描述)' },
  },
  {
    name: 'update_signature',
    description: '修改自己的个性签名',
    parameters: { text: 'string' },
  },
]);

registerReplyRenderer('xingyu', defaultXingYuRenderer);  // 默认就是它，显式注册确认

registerAppSystemPrompt('xingyu', () => {
  const stickers = useStickerStore.getState().packs.flatMap((p) =>
    p.stickers.map((s) => ({ id: s.id, description: s.description })),
  );
  if (stickers.length === 0) return '';
  return (
    '当前可用表情：\n' +
    stickers.map((s) => `${s.id}: ${s.description}`).join('\n')
  );
});
```

XingYu 的 `scheduleAICharacterReply` 迁移：
- 不再直接调 `chatComplete`；改调 `session.send(text)` 拿 `ChatReply`
- 从 `reply.raw` 走现有 `parseReply` 拿 items（兼容现有 bubble 投递逻辑）
- 把最终 UI 投递完的 bubble 依然 append 到 `xingYuDataStore.messages[]`（富类型）；memoryStore 的 assistant 写入由 session 的 mirror=true 已完成（rendered 形态）

session 内部 mirror=true 默认行为：每次 send/replyToLast 完成后，自动写 `{role:'assistant', content: reply.rendered}` 到 memoryStore。XingYu **不需要手动** append raw —— 和 M4.1 的做法相反（M4.1 XingYu 要自己 append raw）。

## XingYu 迁移对照

| 位置 | M4.1 | M4.2 |
|---|---|---|
| XingYu init | 无 AI 注册动作 | 注册 tools (`sticker` + `update_signature`) / renderer / appSystemPrompt |
| `scheduleAICharacterReply` 调 AI | 直接 `chatComplete(messages)` | `session = chatWithCharacter(charId, { persistent: true })`；`reply = await session.send(userText, { mirror: true })` |
| XingYu 写 memoryStore 的 raw assistant entry | 手动 `useCharacterMemory.append(...)` with raw | 由 session 自动写 `reply.rendered` |
| UI 侧 bubble 投递 | parseReply(rawReply) → 多 bubble → 直接 setState | `parseReply(reply.raw)` 然后同现有投递（不变） |
| 表情包清单进 prompt | 硬编码在 `buildSystemBlock` chunk 8 | 走 `registerAppSystemPrompt('xingyu', ...)` 动态生成（放 chunk 6.5 里） |
| 签名更新进 action 流 | `{"type":"signature","text":...}` 特殊 dispatch | 统一为 `{"type":"action","name":"update_signature","params":{"text":...}}`；parseReply 依然识别旧格式做兼容 |

## Demo fixture · `ai-auction-app`

完整展示"非 XingYu 格式 app"的 AI 集成：

```tsx
// ai-auction-app/App.tsx
import { registerTools, registerReplyRenderer, registerAppSystemPrompt,
         chatWithCharacter, injectSystemEvent } from '@hiphone/ai';

const APP_ID = 'ai-auction';

registerTools(APP_ID, [
  { name: 'bid_call', description: '宣布叫价',
    parameters: { item: 'string', min: 'number' } },
  { name: 'accept_bid', description: '接受出价',
    parameters: { bidder: 'string', amount: 'number' } },
  { name: 'hammer_down', description: '落槌成交',
    parameters: { item: 'string', winner: 'string', final: 'number' } },
]);

registerReplyRenderer(APP_ID, {
  render(raw, ctx) {
    const items = parseReply(raw);
    return items.map((i) => {
      if (i.type === 'text') return `${ctx.speakerName}: ${i.content}`;
      if (i.type === 'action') {
        const ps = Object.entries(i.params)
          .map(([k, v]) => `${k}=${JSON.stringify(v)}`).join(' ');
        return `${ctx.speakerName}: 【${i.name}】${ps}`;
      }
      return '';
    }).join('\n');
  },
});

registerAppSystemPrompt(APP_ID, () => {
  const items = useAuctionStore.getState().items;
  return (
    '你是一场拍卖会主持人。\n' +
    '拍品：\n' +
    items.map((i) => `#${i.id} ${i.name}（起拍 ${i.startPrice}）`).join('\n') +
    '\n规则：每次加价至少 10%，三次无人应则落槌。'
  );
});

// UI
export default function AuctionApp() {
  const [s] = useState(() => chatWithCharacter(getAuctioneerId(), { persistent: true }));
  // ...
  const handleBid = async (amount) => {
    const reply = await s.send(`我出 ${amount} 两`);
    for (const a of reply.actions) {
      if (a.name === 'accept_bid') useAuctionStore.getState().acceptBid(a.params);
      if (a.name === 'hammer_down') useAuctionStore.getState().hammerDown(a.params);
    }
    displayNarration(reply.text);
  };
  // ...
}
```
