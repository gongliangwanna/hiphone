# M4.3 §1 — Heartbeat 迁入 Tool Registry · Design

**Date:** 2026-04-25
**Stage:** M4.3 §1 of 3 (§2 Settings AI 工具页、§3 manifest aiTools 字段随后独立立项)
**Prereqs:** M4.2.5 已落地 · transcript/renderer 修复已合并(HEAD `05e768d`)

---

## Context

心跳 agent(`heartbeatAgent.ts` 588 行 + `heartbeatPrompt.ts` 100 行 + `heartbeatTools.ts` 720 行)用独立的 ReAct 协议运行,绕开了 M4.2 引入的统一基建:

- `heartbeatPrompt.ts` 用 `formatOverride` 替换掉默认的 `[回复格式]` chunk,塞进 `Thought: / Actions: [...]` 的 ReAct 格式。
- `buildHeartbeatTools()` 手搓 `{name, description, params}` 列表,和 `registerTools()` 的 Tool Registry 并行存在。
- `parseReactOutput()` 在 `heartbeatAgent.ts` 里用正则解析 ReAct 输出,和 `parseReply()` 的 `{type, param}` 解析完全独立。

维护成本体现在:
- 加新工具要改三个地方(`buildHeartbeatTools` 描述、`executeTool` switch、`parseReactOutput` 的 fallback)。
- 工具执行出错时,observation 只是字符串拼回 role:user,格式不统一,LLM 不容易区分"这是工具报错"还是"这是用户输入"。
- `formatOverride` 这个参数是**只为心跳一个消费者**存在的,从 `PromptInput` 到 `buildSystemBlock` 三处分支都在让路。

迁移目标:心跳和 XingYu / ai-auction 一样,走 `registerTools` + `registerAppSystemPrompt` + `parseReply({type, param})`。

**顺带红利:** 同时扩展 Tool Registry 支持"动态工具上下文"(第三方 app 注册进 heartbeat 池的工具能自己把运行时状态告诉 LLM,比如"当前可聊角色")——这是 heartbeat 自己那 13 个工具里 `chat_with_character` / `view_moments` / `view_notes` 的 alias 登记机制所必须的能力。

---

## Non-goals

- **Provider-native tool calling**(OpenAI function calling / Anthropic tool_use)—M4.3 scope 明确推迟。
- **Streaming 重新设计**—M4.3 scope 明确推迟。
- **Heartbeat 调度器改动**(Web Worker、visibility API、30s tick、per-character interval)—零改动。
- **`heartbeat_log` 日记总结**(后循环生成 narrativeSummary、走 `_appendMessage`)—零改动。
- **Heartbeat alias 系统**(m1/c1/n1)—保留现有逻辑,只是登记入口从 `formatOverride` 构造器迁到 tool 的 `dynamicContext`。
- **Settings → AI → 工具页面**(M4.3 §2)、**manifest.aiTools 静态字段**(M4.3 §3)—独立 spec。

## Design

### D1. Tool Registry API 扩展:`dynamicContext` + `contextAtTail`

**位置:** `src/platform/ai/toolRegistry.ts`

```ts
export interface ToolBuildContext {
  appId: string;
  /**
   * 本次 prompt 是为哪个角色组装的。对 heartbeat 就是正在跑心跳的那个角色;
   * 对普通 chat session 就是 chat 的对方 character。
   */
  characterId: string;
}

export interface ToolDefinition {
  type: string;
  description: string;              // 静态,进 [可用动作]
  param: string;                     // 静态,进 [可用动作]
  /**
   * 运行时可变的上下文。返回 null / '' 表示本次无内容要说,平台会跳过。
   * 每次 assemblePrompt 调用时都会跑一次 → KV 缓存会 miss,慎用。
   */
  dynamicContext?: (ctx: ToolBuildContext) => string | null;
  /**
   * true:`dynamicContext` 输出放 prompt 末端(紧邻 user turn 前),
   *      LLM 关注度最高,适合"希望被频繁触发"的工具(未读消息提醒、倒计时等)。
   * 默认(undefined / false):放 system block 内、[可用动作] chunk 之后 →
   *      标准关注度。
   */
  contextAtTail?: boolean;
}
```

**向后兼容:** 现存 XingYu / ai-auction / notifier 的 `{type, description, param}` 字符串 description 继续生效,两个新字段都可选。

**规则记进 `src/platform/ai/CLAUDE.md`:**

1. 只有状态"每次 prompt 都可能变"的工具才用 `dynamicContext`。Session 级不变的数据(如 XingYu sticker 清单)走 `registerAppSystemPrompt` —— appSystemPrompt 在 session 创建时冻结一次,KV 缓存仍然命中。
2. `dynamicContext` 函数**必须是纯读**(只 `getState()` 取状态,不得 `setState`/`markRead`/持久化写入)。这段在 prompt-build 时跑,每次 LLM 调用都会执行一次——任何副作用都会重复发生 N 次。副作用(例如 mark-as-read、alias 登记)要么留在 tool executor,要么在 runner 级别的 per-heartbeat setup 里处理。
3. 例外:`chat_with_character.dynamicContext` 登记 c1/c2 aliases 属于"纯内存索引建立",只要角色列表顺序稳定就是幂等的,可以接受。

### D2. promptAssembly 两处 chunk 注入

**位置:** `src/platform/ai/promptAssembly.ts`

**System block(`buildSystemBlock`):**

现在的 `[可用动作]` 渲染:
```ts
const toolLines = availableTools!.map((t) => {
  const paramLine = t.param ? `\n  param: ${t.param}` : '';
  return `- ${t.type}: ${t.description}${paramLine}`;
});
chunks.push(`[可用动作]\n${toolLines.join('\n')}`);
```

迁移后保持原样 —— `description` / `param` 不再接受函数形式,静态字符串如常。紧跟着新增一段:

```ts
// [工具状态] — 默认位置(contextAtTail 未设)
const inlineCtxLines: string[] = [];
for (const t of availableTools!) {
  if (!t.dynamicContext || t.contextAtTail) continue;
  const body = t.dynamicContext({ appId, characterId: currentCharId });
  if (body?.trim()) {
    inlineCtxLines.push(`[${t.type}]\n${body.trim()}`);
  }
}
if (inlineCtxLines.length > 0) {
  chunks.push(`[工具状态]\n${inlineCtxLines.join('\n\n')}`);
}
```

**Post-history(`buildPostHistory`):** 在现有 deviceContext / sceneHint 后面、user turn 前面插尾部工具状态:

```ts
// 现有顺序:
//   character.postHistoryInstructions
//   aiConfig.postHistoryInstructions
//   [当前时间:...]
//   deviceContext
//   sceneHint
// 新增:
//   [工具状态 - 高关注]   ← 当任何 tool 的 contextAtTail:true 有内容时
```

签名扩展为:
```ts
function buildPostHistory(
  character, aiConfig, now,
  deviceContext?, sceneHint?,
  tailContext?: string,  // 新增参数
): string { ... }
```

`assemblePrompt` / `inspectPrompt` 先聚合尾部上下文:
```ts
const tailCtxLines: string[] = [];
for (const t of availableTools ?? []) {
  if (!t.dynamicContext || !t.contextAtTail) continue;
  const body = t.dynamicContext({ appId, characterId: currentCharId });
  if (body?.trim()) {
    tailCtxLines.push(`[${t.type}]\n${body.trim()}`);
  }
}
const tailContext = tailCtxLines.length > 0
  ? `[工具状态]\n${tailCtxLines.join('\n\n')}`
  : undefined;
```

- `PromptInput.formatOverride?: string` → 删

### D4. Heartbeat 注册(新文件 `src/platform/ai/heartbeatRegister.ts`)

`registerHeartbeatAi()`:idempotent 注册,在 `App.tsx` 启动时或心跳调度器启动前调一次。共 15 个 tool(14 个业务 + `done`);上游 scope 文档里写的"13 个工具"实际 count 为 14(见 `heartbeatTools.ts` `buildHeartbeatTools`),本 spec 以代码为准。

```ts
const HEARTBEAT_APP_ID = 'heartbeat';

export function registerHeartbeatAi(): void {
  if (registered) return; registered = true;

  registerTools(HEARTBEAT_APP_ID, [
    // 所有静态 tool 用字符串 description;13 个 + done
    { type: 'send_message',   description: '给用户发一条消息(这里的"用户"指玩家,不是其他 AI 角色)', param: '{text: string}' },
    { type: 'post_moment',    description: '发一条星球动态(朋友圈)', param: '{text: string}' },

    { type: 'view_moments',   description: '分页查看星球动态,每页 5 条', param: '{page: number}' },
    { type: 'like_moment',    description: '给某条动态点赞(先 view_moments 获取编号)', param: '{momentId: string}' },
    { type: 'comment_moment', description: '给某条动态评论(先 view_moments 获取编号)', param: '{momentId: string, text: string}' },

    { type: 'view_user_signature',         description: '查看用户当前个性签名', param: '' },
    { type: 'view_user_signature_history', description: '查看用户的历史个性签名', param: '' },
    { type: 'update_signature',            description: '修改自己的个性签名',     param: '{text: string}' },

    { type: 'view_notes',  description: '分页查看自己的备忘录', param: '{page: number}' },
    { type: 'create_note', description: '创建一条备忘录',       param: '{title: string, body: string}' },

    { type: 'view_characters',
      description: '查看可以聊天的其他角色列表',
      param: '' },

    // chat_with_character 用 dynamicContext 生成角色清单 + 登记 c1/c2 aliases
    { type: 'chat_with_character',
      description: '和另一个 AI 角色私聊(想找其他角色说话用这个,不是 send_message)',
      param: '{characterId: string, message: string}',
      dynamicContext: (ctx) => {
        const others = useCharacterStore.getState().characters
          .filter((c) => c.id !== ctx.characterId);
        if (others.length === 0) return '(当前没有其他角色可聊)';
        const aliasMap = getCharacterAlias(ctx.characterId);
        aliasMap.clear();
        const lines = others.map((c, i) => {
          const alias = `c${i + 1}`;
          aliasMap.set(alias, c.id);
          const sig = useXYData.getState().characterSignatures[c.id]?.current;
          return `- [${alias}] ${c.name}${sig ? ` 签名:「${sig}」` : ''}`;
        });
        return `当前可聊角色:\n${lines.join('\n')}\n用 c1、c2... 作为 characterId`;
      },
    },

    // view_unread_messages / view_unread_interactions — contextAtTail:true
    // 让 LLM 对"有未读"这个事实保持高关注。
    // ⚠️ dynamicContext 必须是纯读(不得 mark-as-read),否则 prompt-build
    //   就把未读消费掉了;mark-as-read 留在 executor。
    { type: 'view_unread_messages',
      description: '查看用户发给你的未回复消息',
      param: '',
      dynamicContext: (ctx) => {
        const count = computeUnreadMsgCount(ctx.characterId);  // 纯读
        return count > 0 ? `用户有 ${count} 条未回复消息给你` : null;
      },
      contextAtTail: true,
    },
    { type: 'view_unread_interactions',
      description: '查看你的动态收到的互动通知',
      param: '',
      dynamicContext: (ctx) => {
        const n = computeUnreadInteractionCount(ctx.characterId);  // 纯读
        return n > 0 ? `你有 ${n} 条新的动态互动` : null;
      },
      contextAtTail: true,
    },

    { type: 'done', description: '结束本次心跳,不再执行其他操作', param: '' },
  ]);

  registerAppSystemPrompt(HEARTBEAT_APP_ID, () => {
    const persona = usePersonaStore.getState().getActivePersona();
    const userName = persona?.name ?? '用户';
    return [
      '你现在处于"自主行为"模式。你不是在和用户聊天,而是在自由活动时间。',
      `用户的名字是${userName}。`,
      '你可以自主决定做什么:浏览朋友圈、发动态、给别人点赞评论、主动给用户发消息、和其他角色聊天、更新个性签名、写备忘录记录想法等。',
      '请像一个真实的人一样自然地行动。不需要每次都做很多事,有时候只是看看就好。',
      '',
      '[行为约束]',
      '- 保持角色性格,用符合人设的方式行动',
      '- 主动发消息要自然,不要太频繁或太刻意',
      '- 发动态要像真人发朋友圈,内容自然真实',
      '- 不要每次心跳都做很多事,有时候看看就够了',
      '- 签名不要改太频繁,只在心情变化时更新',
      '- 想找其他角色说话必须用 chat_with_character,send_message 只能给用户发消息。不要搞混!',
      '- 可以先查看未读消息和互动通知,了解情况后再决定做什么',
      '- 可以一次执行多个操作,但不要一次做太多',
      '- 想结束本次心跳,调用 done',
    ].join('\n');
  });
}
```

`chat_with_character` 和 `view_moments` / `view_notes` 的 `dynamicContext` 副作用(修改 alias map)在 prompt-build 时跑。注意这个时机比"执行工具时"更早——登记完 aliases 之后,下一轮 LLM 就能引用 `c1`/`m1` 这些别名。

### D6. Heartbeat runner 重写

**位置:** `src/platform/ai/heartbeatAgent.ts`

```ts
import { registerHeartbeatAi, HEARTBEAT_APP_ID } from './heartbeatRegister';
import { executeHeartbeatTool, resetHeartbeatLimits, uid } from './heartbeatTools';
import { parseReply, type ReplyItem } from './replyParser';
import { getTools } from './toolRegistry';
import { getAppSystemPrompt } from './appSystemPromptRegistry';
// ... 其他 imports 不变

// 启动时注册(idempotent)
registerHeartbeatAi();

async function runHeartbeat(characterId: string, signal: AbortSignal): Promise<void> {
  // ... 现有 config / character / aiConfig / adapter / persona / worldBookChunk 不变

  resetHeartbeatLimits(characterId);

  const frozenTools = getTools(HEARTBEAT_APP_ID);
  const frozenAppSystemPrompt = getAppSystemPrompt(HEARTBEAT_APP_ID)?.() ?? undefined;
  const knownTypes = new Set(frozenTools.map((t) => t.type));

  const { messages: chatMessages } = assemblePrompt({
    character: { ... },
    persona: { ... },
    aiConfig: { ... },
    worldBookChunk,
    memoryEntries,
    currentCharId: characterId,
    charactersById,
    now: new Date(),
    deviceContext: buildDeviceContext(),
    availableStickers: allStickers.length > 0 ? allStickers : undefined,

    // 新:走统一基建,不再用 formatOverride
    currentAppId: HEARTBEAT_APP_ID,
    availableTools: frozenTools,
    appSystemPromptSnapshot: frozenAppSystemPrompt,
  });

  // Trigger hack 保留(§1 scope 控制)
  const messages: ChatMessage[] = chatMessages.filter((m) => m.role !== 'user');
  messages.push({ role: 'user', content: '你现在处于自主行为时间。请决定你现在要做什么。' });

  useHeartbeatStore.getState().setRunning(characterId, 0);

  const actionsTaken: { action: string; detail: string }[] = [];

  for (let i = 0; i < config.maxIterations; i++) {
    if (signal.aborted) break;
    useHeartbeatStore.getState().setRunning(characterId, i + 1);

    let rawReply: string;
    try {
      rawReply = await chatComplete({ ... }, messages, { ... }, signal);
    } catch (e) {
      if ((e as Error)?.name === 'AbortError') break;
      pushLog(characterId, 'error', `LLM 调用失败: ${...}`);
      break;
    }

    // 新:用统一 parseReply
    const { items, error } = parseReply(rawReply, knownTypes);
    if (error !== null) {
      // 解析失败:以 role:system 喂回错误,让下一轮自我纠偏;in-memory 不持久化
      messages.push({ role: 'assistant', content: rawReply });
      messages.push({ role: 'system', content: buildParseErrorMessage(error, [...knownTypes]) });
      pushLog(characterId, 'parse_error', rawReply.slice(0, 80));
      continue;   // 重试下一轮
    }

    // 执行所有 item,收集 observations
    const observations: string[] = [];
    let hitDone = false;

    for (const item of items) {
      if (signal.aborted) break;

      if (item.type === 'done') {
        pushLog(characterId, 'done', '');
        hitDone = true;
        break;
      }

      const result = await executeHeartbeatTool(item.type, item.param, characterId, signal);
      actionsTaken.push({ action: item.type, detail: formatActionDetail(item, characterId) });
      observations.push(`[${item.type}] ${result.observation}`);
      if (result.done) { hitDone = true; break; }
    }
    if (hitDone) break;

    messages.push({ role: 'assistant', content: rawReply });
    // 新:observations 走 role:system(不再伪装成 user)
    messages.push({
      role: 'system',
      content: observations.length === 1
        ? `Observation: ${observations[0]}`
        : `Observations:\n${observations.join('\n')}`,
    });
  }

  // ── heartbeat_log 日记总结 —— 逻辑不变 ──
  // ...(narrativeSummary 生成 + _appendMessage 写入)
}
```

**`formatActionDetail`:** 签名改成接 `ReplyItem`(param 不再是 `Record<string, unknown>` 而是 `unknown`)。内部加 type guard 把 param 收窄成期望 shape 再取字段。

**`buildParseErrorMessage`:** 复用 `src/platform/userApp/sdk/ai.ts` 里已有的同名私有函数——提升为 `src/platform/ai/parseErrorMessage.ts` 独立模块,两处共用。
